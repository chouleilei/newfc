# 财务实际数自动转换实施方案

## 1. 目标

建立一条可复现、可审核、可阻断、可追溯的月度实际数流水线：

```text
财务系统余额表 + 官方利润表
          ↓
财务源适配器解析
          ↓
标准化财务明细
          ↓
已审核并锁定的组织/科目映射版本
          ↓
组织编码 × 预算科目编码汇总
          ↓
完整性、金额守恒和利润表勾稽
          ↓
生成标准实际数 Excel
          ↓
复用现有导入预览 → 人工确认 → 原子提交/撤销
```

本方案不改变现有实际数的存储口径：金额在后端仍以整数分存储，数量仍按 `10^4` 缩放，历史快照仍绑定不可变树快照。

## 2. 设计原则

1. **AI 只提建议**：AI 用于首次映射和新增科目的候选推荐，不读取月度金额，不执行正式转换，不直接写库。
2. **正式数据全程确定性**：解析、借贷方向、映射、拆分、尾差和汇总全部由固定程序执行。
3. **失败关闭**：任一强制校验失败时，转换批次标记为 `blocked`，不允许进入导入预览。
4. **映射必须版本化**：每个转换批次绑定一个已锁定映射版本，新增或修改映射必须创建新版本。
5. **来源金额守恒**：每条非零来源记录必须且只能被处理一次，拆分前后必须分毫不差。
6. **有依据才拆分**：只支持辅助核算驱动、明细表驱动或已审批固定比例的拆分；无依据的拆分进入人工待处理清单。
7. **转换和入库分层**：转换层产出标准 Excel 和勾稽报告；入库继续复用现有预览、确认、快照和撤销链路。

## 3. 开发边界

### 3.1 本期范围

- 支持一种已确认的财务系统余额表格式。
- 支持一种已确认的官方利润表格式。
- 支持财务科目和辅助核算条件到预算科目的直接、合并和有依据拆分。
- 支持历史组织名称/账套/核算组织到叶子组织编码的映射。
- 支持映射草稿、审核锁定、复制新版本和停用。
- 支持 AI 候选映射文件的生成和人工审核导入。
- 支持转换批次、原始文件哈希、映射版本、校验结果和下游导入批次的全链路留痕。

### 3.2 本期不做

- 不自动登录财务系统或模拟点击导出。
- 不让 LLM 参与月度金额转换。
- 不对无辅助维度、无明细依据的金额自动猜测拆分。
- 不建设“任意 Excel 通用智能解析”，每种来源格式必须有显式适配器。
- 不绕过现有实际数导入批次直接写入 `actual_current`。

## 4. 前置输入和样本契约

开始编写解析器前，将以下脱敏文件固定为测试 fixture：

- 至少三个不同月份的余额表，包含年初、年中和存在冲销/负数的月份。
- 与上述余额表同期的官方利润表。
- 财务科目完整清单，含编码、名称、层级、科目性质和是否末级。
- 组织、核算项目和辅助核算值清单。
- 已知的合并、拆分、更名、停用和特殊借贷方样例。

每个适配器都必须定义并校验：

- 工作表名称或匹配规则。
- 表头行和必填列别名。
- 数据起始行、汇总行判断和空行策略。
- 年度、截止日期和账套的取值位置。
- 金额单位、负数格式和 Excel 公式单元格策略。

## 5. 数据模型

在 `backend/src/db/migrations.ts` 新增迁移，表名统一使用 `finance_` 前缀。

### 5.1 `finance_source_profile`

财务数据源和解析配置。

| 字段 | 用途 |
|---|---|
| `id/code/name` | 数据源标识 |
| `adapter_type` | 后端白名单适配器类型 |
| `config_json` | sheet/表头别名/日期等声明式配置 |
| `status` | `active/inactive` |
| `created_at/updated_at` | 审计时间 |

`adapter_type` 必须映射到后端内置实现，`config_json` 不允许保存或执行用户代码。

### 5.2 `finance_mapping_version`

| 字段 | 用途 |
|---|---|
| `source_profile_id/version_no/name` | 版本身份 |
| `status` | `draft/locked/retired` |
| `org_tree_snapshot_id/account_tree_snapshot_id` | 目标树口径 |
| `parent_version_id` | 新版本来源 |
| `created_by/reviewed_by` | 创建与复核人 |
| `created_at/locked_at` | 时间留痕 |

只有 `draft` 可修改；只有通过完整性检查的草稿可锁定；已锁定版本永不原地修改。

锁定动作必须在同一事务中固化报表指标定义。组织、科目层级从版本绑定的 `tree_snapshot` 读取，指标及其公式项从 `finance_metric_snapshot` / `finance_metric_term_snapshot` 读取；后续主数据重挂父级、停用节点或编辑指标公式，不得改变已锁定版本的勾稽结果。

### 5.3 `finance_org_mapping`

| 字段 | 用途 |
|---|---|
| `mapping_version_id` | 所属版本 |
| `source_book_code` | 源账套/公司编码 |
| `source_org_code/source_org_name` | 源组织或历史名称 |
| `source_aux_json` | 可选的辅助条件 |
| `target_org_id` | 目标叶子组织 |
| `priority` | 特定规则优先于通用规则 |
| `note` | 映射依据 |

锁定前校验目标组织属于版本绑定树快照的叶子节点，且规则之间不存在同优先级冲突。

### 5.4 `finance_account_mapping`

| 字段 | 用途 |
|---|---|
| `mapping_version_id` | 所属版本 |
| `source_account_code/source_account_name` | 源财务科目 |
| `source_aux_json` | 辅助核算匹配条件 |
| `target_account_id` | 目标叶子预算科目 |
| `amount_rule` | `credit/debit/credit_minus_debit/debit_minus_credit` |
| `allocation_method` | `direct/fixed_ratio` |
| `allocation_weight` | 定点整数权重，禁止浮点数 |
| `priority/status/note` | 优先级、状态和判断依据 |

一个来源条件可以对应多个目标行，但只有 `fixed_ratio` 允许一对多，同组权重之和必须等于固定缩放基数。尾差按“最大余数 + 稳定目标编码顺序”确定性分配。

`inactive` 规则仅作为版本沿革记录，不参与锁定前的目标、冲突、权重或跨分类校验，也不参与运行时匹配；替换旧规则时可保留停用行并新增有效规则。

### 5.5 `finance_reconciliation_rule`

定义官方利润表项目与预算科目/指标的勾稽关系，包含来源行别名、目标编码、组织范围、比较方式和允许差异。

默认强制金额误差为 `0` 分。只有官方报表确实仅提供四舍五入展示值时，才允许在规则中明示配置容差并记录原因。

### 5.6 `finance_conversion_batch`

| 字段 | 用途 |
|---|---|
| `source_profile_id/mapping_version_id` | 解析和映射口径 |
| `year/snapshot_date` | 目标期间 |
| `status` | `parsing/blocked/validated/imported/cancelled` |
| `balance_name/balance_sha256/balance_blob` | 余额表原件 |
| `profit_name/profit_sha256/profit_blob` | 利润表原件 |
| `journal_name/journal_sha256/journal_blob` | 可选序时簿原件 |
| `normalized_json` | 标准化中间结果 |
| `validation_json` | 勾稽和异常报告 |
| `output_sha256/output_blob` | 标准导入文件 |
| `import_batch_id` | 关联现有 `import_batch` |
| `created_at/validated_at/imported_at` | 状态时间 |

原件是追溯依据，不在请求结束时删除。文件大小上限沿用导入安全限制，并在转换批次撤销/保留策略中明确处理。

同数据源、同年度、同截止日存在成功批次时，新批次必须以该期间最新的 `validated/imported` 批次作为 `revision_of_id`；若该期间没有成功批次则禁止传入修订 ID，防止首批伪造或跨数据源、跨期间串联审计链。

### 6.1 标准化中间类型

```ts
interface NormalizedFinanceRow {
  sourceSheet: string;
  sourceRow: number;
  bookCode: string;
  orgCode: string;
  orgName: string;
  accountCode: string;
  accountName: string;
  auxiliary: Record<string, string>;
  cumulativeDebitCents: number;
  cumulativeCreditCents: number;
  year: number;
  snapshotDate: string;
}
```

每个输出行保留来源 sheet 和行号，校验报告必须能反查到原 Excel 位置。

### 6.2 转换顺序

1. 验证文件类型、大小、工作表和必填表头。
2. 解析余额表和利润表，所有金额转为整数分。
3. 校验年度、截止日期、账套和组织范围一致。
4. 按优先级匹配组织规则，要求唯一命中。
5. 按优先级匹配科目+辅助条件，要求唯一规则组命中。
6. 根据 `amount_rule` 计算展示口径金额：收入通常为净贷方，成本费用通常为净借方，具体以已审核规则为准。
7. 执行直接映射或固定比例拆分，记录每条来源的去向。
8. 按 `year + snapshotDate + orgCode + accountCode` 汇总。
9. 执行全部强制校验。
10. 只在全部通过时生成标准 Excel 和输出 SHA-256。

## 7. 校验闸门

### 7.1 解析层

- 必填表头全部存在，且没有多义列。
- Excel 公式单元格必须存在缓存计算值，否则阻断。
- 金额格式、年度和日期全部合法。
- 来源末级科目与汇总行不重复计数。
- 空白、隐藏和合计行的处理符合适配器契约。

### 7.2 映射层

- 每条非零来源行组织映射唯一命中。
- 每条非零来源行科目映射唯一规则组命中。
- 不允许未映射、多重命中、停用目标或非叶子目标。
- 目标组织与科目必须通过现有适用范围校验。
- 金额科目不得映射到 `quantity` 科目。

### 7.3 金额守恒

- 每条来源行：转换前金额 = 所有目标分配金额之和。
- 每个财务科目：来源净额 = 映射后合计。
- 每个来源组织：来源净额 = 映射后合计。
- 全批次：收入、成本和费用分类守恒，不仅比较净利润。

### 7.4 利润表勾稽

按财务官方报表可用粒度执行：

- 营业收入。
- 营业成本。
- 税金及附加。
- 销售、管理和财务费用。
- 投资收益、营业外收支和所得税。
- 营业利润、利润总额和净利润。

同时运行项目现有 `P01~P07` 口径计算，但官方利润表是外部基准，不能只用系统内部公式自我证明。

### 7.5 重复和时间顺序

- 相同数据源下，已成功导入的 `balance_sha256 + profit_sha256 + mapping_version_id` 默认禁止重复。
- 同一数据源、年度和截止日期已有成功批次时，只允许以“修订”语义创建新批次。
- 普通导入截止日期不得早于当前最新截止日期，历史补录继续走现有显式模式。

## 8. 完整累计文件与现有 `upsert`

现有 Excel 导入使用 `upsert`，本次文件中没有出现的旧组织科目值不会自动清除。财务余额表是完整累计口径，必须解决残留值问题。

本期采用以下可审计策略：

1. 每个数据源声明其拥有的叶子组织和目标科目范围。
2. 转换文件对拥有范围内的所有有效组织科目组合输出完整快照，当月为零时显式输出 `0.00`。
3. 现有服务会对显式零值执行删除，从而清理上月残留值。
4. 转换前检查拥有范围与其他财务数据源是否冲突，并在导入预览中显示将清零的组合。
5. 如拥有范围内存在后续手工修改，确认导入前阻断并要求处理冲突，不静默覆盖。

由于当前组织科目矩阵规模接近单文件 5000 行上限，开发时应同时将该上限改为可配置安全上限，并以输出字节数和实际解析行数双重限制。

后续如需要多数据源细粒度共存，再将此策略升级为 `replace_scope`业务操作，不在本期直接对整个年度使用 `replace`。

## 9. AI 候选映射流程

1. 从解析器输出去重后的财务科目、层级和辅助维度，不输出金额。
2. 读取当前预算科目树、组织树、适用范围与相关文档。
3. AI 为每个源项输出最多三个候选，包含理由、置信度、歧义和是否需要拆分。
4. 脚本使用 JSON Schema 校验 AI 输出，未知目标编码直接拒绝。
5. 生成“待审核映射.xlsx”，不直接写正式映射表。
6. 人工审核后导入草稿版本，再经程序完整性检查后锁定。

AI 输出的理由和置信度只作审核材料，不影响正式转换算法。模型、提示词版本和生成时间写入候选文件元数据。

## 11. 前端设计

新增“财务数据转换”页面，不把功能塞入现有实际数编辑矩阵。

### 11.1 映射管理

- 版本列表：草稿、已锁定、已停用。
- 组织映射表：突出历史名称、未映射和多重匹配。
- 科目映射表：展示源层级、候选、目标路径、金额规则、拆分比例和审核说明。
- 锁定前检查抽屉：一次显示全部阻断错误，不逐个弹错。

### 11.2 月度转换

1. 选择数据源和已锁定映射版本。
2. 上传余额表和利润表。
3. 显示解析行数、组织数、财务科目数、输出组合数和文件哈希。
4. 分区展示阻断错误、警告、金额守恒和利润表勾稽结果。
5. 只有通过时才显示“下载标准文件”和“创建导入预览”。
6. 进入现有导入预览，继续由人工点击确认。

勾稽结果适合使用对比表，列为“项目/官方数/映射数/差额/结果”；映射详情使用可筛选明细表，不用图表表达精确金额。

## 12. CLI 与页面的关系

先完成可独立运行的服务层和 CLI，再接前端；CLI 不实现另一套转换逻辑。

```bash
cd backend
npx ts-node scripts/inspect-finance-export.ts --file <balance.xlsx> --profile <code>
npx ts-node scripts/convert-finance-actuals.ts \
  --balance <balance.xlsx> \

  --profile <code> \
  --mapping-version <id> \
  --output <actual-import.xlsx>
```

CLI、API 和测试全部调用 `convert.service.ts`，保证只存在一套生产算法。

## 13. 导入链路补强

### 13.1 SHA-256 去重

当前 `import_batch.sha256` 只留痕，不阻止重复。新链路在创建转换批次和导入预览时都做应用层去重检查。

不直接对 `import_batch.sha256` 建立全局唯一索引，因为已取消、已撤销和经审批的修订可能需要保留相同文件记录。

### 13.2 预览内容

现有预览在导入转换文件时扩展显示：

- 新增、修改和清零数量。
- 按组织和预算根科目汇总的变化额。
- 来源余额表、利润表和映射版本。
- 勾稽通过标记和转换批次 ID。

### 13.3 撤销关联

导入批次撤销后，转换批次保留，但显示下游已撤销。不删除原件、输出文件和勾稽报告，以便追溯。

## 14. 测试计划

### 14.1 单元测试

- 表头别名、隐藏行、合并单元格、公式缓存值和空行。
- 元/万元、千分位、括号负数、负号和空值。
- 四种 `amount_rule` 及收入/成本费用冲销。
- 组织和科目规则的优先级、唯一命中和冲突。
- 固定比例拆分的尾差和金额守恒。
- 零值快照行、重复来源和日期顺序。
- 利润表精确匹配、容差和差异报告。

### 14.2 集成测试

- 真实脱敏余额表 → 标准 Excel 的黄金文件测试。
- 标准 Excel 经现有 `parseActualImport`/`resolveActualImport` 再校验。
- 转换批次 → 导入预览 → 确认 → 快照 → 撤销全链路。
- 上月有值、本月为零时能正确清理旧值。
- 拥有范围外的手工数据不被清理。
- 映射版本锁定后不可修改，历史批次可复现。
- 锁定后重挂科目或编辑指标公式，重复转换的勾稽结果保持不变。
- 单层余额表同科目多组织/辅助行先汇总，再与序时簿逐科目核验。
- 停用映射不参与校验；不存在同源同期间成功批次时拒绝修订 ID。
- 同文件重复提交被阻断，修订和撤销语义正确。

### 14.3 失败测试

- 缺少列、未知工作表、无公式缓存值。
- 未映射科目/组织、映射多重命中。
- 目标为汇总节点、停用节点或不适用组织。
- 拆分比例不守恒、勾稽差一分。
- 年度已冻结、日期倒退、输出超限。
- 在预览后映射口径或目标数据已变化时禁止确认。

## 15. 开发阶段与验收门

### 阶段 A：样本契约和解析器

交付：

- 脱敏 fixture。
- 数据源 profile 和适配器。
- `inspect-finance-export.ts`。
- 余额表/利润表标准化结果和错误报告。

验收门：三个样本月份可重复得到一致结果，异常单元格会显式失败，不静默跳过。

### 阶段 B：映射版本和确定性转换

交付：

- 数据库迁移。
- 映射 CRUD、复制、校验和锁定。
- 匹配、金额规则、拆分和尾差算法。
- CSV/Excel 映射导入导出。

验收门：所有非零来源行处理次数等于 1，金额守恒，锁定版本不可变。

### 阶段 C：勾稽、输出和 CLI 闭环

交付：

- 多层勾稽引擎。
- 校验报告。
- 完整零值快照输出。
- `convert-finance-actuals.ts`。
- 现有导入解析器二次验证。

验收门：勾稽差一分即阻断；通过时生成的 Excel 可被现有导入链路无损解析。

### 阶段 D：转换批次与导入联动

交付：

- `finance_conversion_batch` 及 API。
- 原件、哈希、输出和校验报告留痕。
- 重复提交阻断和修订语义。
- 从转换批次创建现有导入预览的联动。

验收门：可从任一导入快照追溯到输出文件、映射版本、余额表和利润表。

### 阶段 E：前端映射审核和月度操作页

交付：

- 映射版本管理页。
- 映射审核与锁定页。
- 月度上传、勾稽结果和批次历史页。
- 下载输出、创建导入预览和跳转确认。

验收门：月度操作人员只需选择文件、查看勾稽结果和确认导入，无需手工编辑任何金额。

### 阶段 F：AI 候选映射

交付：

- 去金额化的 AI 输入包。
- 结构化候选输出校验。
- 待审核 Excel 和导入草稿流程。
- 新增财务科目的增量差异清单。

验收门：AI 结果无法绕过人工审核和版本锁定，关闭 AI 后月度转换仍能完整运行。

### 阶段 G：真实数据并行试运行

交付：

- 用连续多月真实数据与原手工结果并行比较。
- 完成历史风场名称到新组织编码的逐项复核。
- 记录差异原因、更新映射新版本并重跑。
- 形成财务系统导出和月度操作说明。

验收门：连续样本月份全部通过分毫级勾稽，无未映射非零项，零值清理、重复阻断、预览、提交和撤销均通过。

## 16. 开发顺序

严格按以下顺序推进：

1. 样本契约和 fixture。
2. 解析器与标准化类型。
3. 映射数据模型和版本锁定。
4. 确定性匹配、金额规则和拆分。
5. 守恒校验和官方利润表勾稽。
6. 标准 Excel 生成和现有导入链路二次验证。
7. 转换批次、哈希去重和导入联动。
8. 前端月度操作和映射审核。
9. AI 候选映射。
10. 真实数据并行试运行与映射定版。

AI 安排在确定性映射模型之后，因为候选结果必须落入一个已定义、可校验、可锁定的结构；AI 不是解析和转换引擎的前置依赖。

## 17. 完成定义

只有同时满足以下条件，本功能才算完成：

- 固定财务系统的实际导出文件可稳定解析。
- 正式转换不依赖 AI 或人工金额判断。
- 映射版本已审核、锁定且可复现。
- 非零来源行无遗漏、无多重命中，拆分前后分毫不差。
- 官方利润表强制勾稽通过后才能生成导入文件。
- 完整累计快照不会遗留上月数据，也不会清理数据源拥有范围外的数据。
- 重复文件和重复期间受控，修订具有明确语义。
- 转换结果经现有导入链路二次校验，并可预览、原子提交和撤销。
- 可从任意实际数快照追溯到导入批次、转换批次、映射版本和两份财务原件。
- 后端单元/集成测试和前端构建全部通过。
