# 集团多组织年度预算管理系统方案（精简版）

本方案在初版基础上，按真实定位（个人使用、小数据量）做了系统性裁剪。核心设计全部保留：金额整数分存储 + 统一利润方向符号、预算版本绑定树快照、实际数当前值 + 全量快照、历史数据不按当前结构重算。裁剪清单见附录 A。

---

# 一、项目定位

## 1. 建设目标

建设一套个人使用的集团多组织年度预算管理工具，实现：

- 多级组织和多级损益科目管理；
- 年度预算版本编制、过程记录、定稿和切换；
- 截止指定日期的年度累计实际数维护；
- 预算与实际执行情况分析；
- 多年度历史趋势和预算准确性分析；
- 组织、科目、预算和实际口径的历史追溯；
- Excel 导入、导出及本地备份恢复。

## 2. 规模假设（设计基准）

本方案按以下真实数据规模设计，所有性能和存储决策以此为基准：

| 项目 | 规模 |
|---|---:|
| 叶子组织 | 约 20 个，上限 30 |
| 叶子科目 | 约 200 个，上限 250 |
| 预算编辑矩阵 | 约 4 000 单元格，上限 7 500 |
| 实际快照 | 每次全量约 4 000 行，每年 ≤ 60 个 |
| 预算版本 | 每年 ≤ 10 个 |
| 历史年度 | ≤ 20 年 |

最坏情况 20 年累计业务数据行数不超过 1 000 万行，SQLite 单文件轻松承载。矩阵 4 000 单元格对任何表格组件都不构成性能压力，无需为大规模做特殊设计；但架构上保留 10 倍余量，超出时按附录 A 的路径升级。

## 3. 明确边界

首期不包含：

- 内部交易抵消、合并抵消分录；
- 部门预算、月度预算、资产负债表预算、现金流量表预算；
- 总账凭证级明细；
- 多用户协同审批、复杂权限体系；
- **多币种**：首期仅单一币种（人民币），金额精度到分；
- 自定义月度进度模板（仅均匀自然日进度）。

## 4. 支持的数据范围

首期支持三类损益金额科目和一类数量科目：`income`（收入）、`cost`（成本）、`expense`（费用）、`quantity`（数量指标）。数量科目用于电量、电价、税率、人数等非货币指标，不进入金额汇总和利润指标公式。

系统以年度预算和年度累计实际为核心，不保存月度预算明细。实际数据通过不同截止日期的累计快照形成趋势。

# 二、核心设计原则

## 1. 金额统一使用带符号整数

系统内部金额统一以"分"为单位，SQLite `INTEGER` 存储。统一利润方向符号：

- 收入：正数；
- 成本：负数；
- 费用：负数。

| 项目 | 界面录入金额 | 数据库存储金额 |
|---|---:|---:|
| 收入 | 1.00 万元 | 1000000 |
| 成本 | 0.60 万元 | -600000 |
| 费用 | 0.20 万元 | -200000 |

利润计算：`1000000 - 600000 - 200000 = 200000`，即利润 0.20 万元。

界面金额统一以**万元**录入和展示（两位小数），后端和数据库仍以元字符串/整数分传输和存储。结构化 Excel 填报模板沿用万元口径；传统扁平兼容模板和预算导入模板的金额列仍使用元，两种模板均按表头识别。数量按原值录入，最多四位小数，按科目计量单位和汇总方式处理。

录入与展示规则：

- 普通录入模式下用户输入正数，后端按科目类型转换符号（income 为 +1，cost/expense 为 -1）；
- 成本、费用界面正常展示为正数；利润、差异等跨方向指标按带符号计算结果展示；
- 允许录入负的界面金额，用于收入冲减、成本费用冲回、历史更正；
- 金额字符串由后端转换为分（十进制解析，不用浮点乘法）；
- 前后端之间金额一律以字符串传输；数量以缩放整数或数量字符串传输。

## 2. 科目树与指标体系分离

科目树只承担同类科目的层级汇总：

- 收入类父节点下只能挂收入类科目，成本、费用同理；
- 不允许在一个父科目下混合不同类型。

毛利、营业利润、净利润等跨方向项目不作为科目，而是报表指标，由指标公式（科目节点和其他指标的线性组合）计算。由于成本已是负数，指标项直接相加即可，例如毛利 = 营业收入 + 营业成本。

## 3. 年度预算口径固定

预算版本创建时绑定当时的组织树快照和科目树快照，后续始终按绑定的树口径编制、汇总和展示，不受当前主数据调整影响。

版本定稿（存储状态仍为 `locked`）后不可修改，修订通过“基于此版继续编制”生成新草稿完成。一个年度可保留 V1/V2/V3 等多个定稿版本，`is_current` 仅表示其中哪一版当前采用。

## 4. 实际数采用当前值加全量快照

系统维护每个年度当前最新的累计实际值。每次保存或导入当前实际数后，在同一事务中：

1. 更新当前实际表；
2. 创建一个实际快照批次，将该年度所有非零累计实际值全量写入快照明细；
3. 保存快照绑定的组织树和科目树快照；
4. 更新年度当前快照。

快照采用逻辑全量：未出现的组织、科目组合视为零。当前规模下单次快照约 4 000 行，全部快照永久保留，不做归档压缩。

## 5. 历史数据不可被当前结构重算

- 锁定预算版本的报表：按版本绑定的树快照 + 版本明细计算（明细锁定后不可变，结果确定）；
- 已关闭年度的实际报表：按年度关闭时指定的最终快照及其绑定的树快照计算；
- 未关闭年度的实时汇总：按当前树结构计算，保存快照即固化当时口径。

不设独立的冻结汇总表：数据规模小，按需计算为毫秒级，省去"冻结数据与实时数据一致性"这一整类问题。若未来数据量增长 10 倍以上，再引入固化汇总（见附录 A）。

## 6. 后端是业务规则的最终执行者

以下规则由后端执行，前端不作为金额符号和业务状态的可信来源：

- 元转分、金额方向转换；
- 叶子节点校验、树结构合法性校验；
- 预算版本状态校验、年度状态校验；
- 唯一性校验、汇总计算、快照生成；
- Excel 导入校验、操作日志记录。

# 三、业务流程

## 1. 基础资料流程

```text
建立组织树 → 建立损益科目树 → 配置利润类报表指标 → 结构检查
```

## 2. 预算与预测编制流程

```text
创建预算或预测版本（自动绑定当前树快照）
→ 可选择历史预算或当前实际并预览增长生成结果
→ 录入叶子组织 × 叶子科目预算
→ 草稿实时自动保存
→ 在预算讨论节点主动“记录本轮修改”
→ 查看汇总和服务端质量报告
→ 定稿（如有未记录变化则自动补一条定稿前记录）
→ 设为当前生效版本
```

预算与预测各自维护一个当前生效版本。修订锁定版本：

```text
基于定稿版本继续编制 → 生成新草稿 → 修改/记录 → 定稿新版本 → 按需切换当前生效
```

## 3. 当前实际数维护流程

```text
选择年度和截止日期
→ 手工录入，或上传 Excel 生成持久预览批次
→ 校验全部数据并确认同一预览批次
→ 事务内：更新当前实际 + 创建全量快照 + 更新年度当前快照
→ 刷新预算执行报表
```

## 4. 历史快照补录流程

```text
选择年度 → 指定历史截止日期 → 导入历史累计实际
→ 创建历史快照（不覆盖当前实际）
```

## 5. 年度关闭流程

```text
选择年度最终实际快照
→ 完整性检查
→ 年度状态设为 frozen，记录最终快照
→ 历史报表改为读取最终快照
```

# 四、数据模型

共 16 张业务表，另有 `schema_migration`。相对初版删除了 4 张表（冻结汇总相关 2 张、进度模板 2 张），并增加轻量编制记录点、固定测算模板和导入批次，见附录 A。

## 1. 组织表 `org`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| parent_id | INTEGER | 上级组织，根节点为空 |
| code | TEXT | 组织编码，全局唯一且不可变 |
| name | TEXT | 组织名称 |
| sort_order | INTEGER | 同级排序 |
| status | TEXT | active / inactive |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

约束：`code` 唯一；`parent_id` 不能等于自身；禁止循环层级；被业务数据引用后不能物理删除；层级和是否叶子动态计算，不落库。

## 2. 科目表 `account`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| parent_id | INTEGER | 上级科目 |
| code | TEXT | 科目编码，全局唯一且不可变 |
| name | TEXT | 科目名称 |
| type | TEXT | income / cost / expense / quantity |
| unit | TEXT | 数量科目计量单位，金额科目为空 |
| quantity_agg | TEXT | 数量汇总方式：sum / none |
| budget_required | INTEGER | 预算/预测是否必填，0/1 |
| basis_required | INTEGER | 有值时是否必须填写测算依据，0/1 |
| sort_order | INTEGER | 同级排序 |
| status | TEXT | active / inactive |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

约束：`code` 唯一；子科目类型必须与父科目一致；禁止循环层级；被业务数据引用后不能物理删除；是否叶子动态判断；`budget_required` 和 `basis_required` 只允许对叶子科目启用。

## 3. 树快照表 `tree_snapshot`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 快照主键 |
| tree_type | TEXT | org / account |
| content_json | TEXT | 完整树结构 JSON |
| content_hash | TEXT | 内容哈希 |
| created_at | TEXT | 创建时间 |

唯一约束：`(tree_type, content_hash)`，内容未变化时复用已有快照。节点保存 `id、parentId、code、name、type（科目）、unit、quantityAgg、budgetRequired、basisRequired、sortOrder、status`，**包含停用节点**（status=inactive），保证历史口径和填报要求完整。

## 4. 预算版本表 `budget_version`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| year | INTEGER | 预算年度 |
| name | TEXT | 版本名称 |
| status | TEXT | draft / locked / archived |
| is_current | INTEGER | 是否当前生效 |
| kind | TEXT | budget / forecast，默认 budget |
| org_tree_snapshot_id | INTEGER | 绑定的组织树快照 |
| account_tree_snapshot_id | INTEGER | 绑定的科目树快照 |
| source_version_id | INTEGER | 复制来源版本，可空 |
| generation_json | TEXT | 草稿生成方式与参数摘要 |
| note | TEXT | 备注 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |
| locked_at | TEXT | 锁定时间 |

约束：同年度版本名称唯一；每年度、每种 `kind` 最多一个 `is_current=1`；只有锁定版本可设为当前生效；当前生效版本不能直接归档；锁定版本不能修改和删除；版本创建后不改变绑定树快照。预算与预测只区分用途，复用相同明细、快照和生命周期。

## 5. 预算明细表 `budget_entry`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| version_id | INTEGER | 预算版本 |
| org_id | INTEGER | 叶子组织 |
| account_id | INTEGER | 叶子科目 |
| amount_cents | INTEGER | 带符号预算金额 |
| quantity | INTEGER | 数量型预算值，按 10^4 缩放；金额科目为空 |
| formula | TEXT | 单元格测算公式，可空 |
| note | TEXT | 测算依据/附注 |
| updated_at | TEXT | 更新时间 |

唯一约束：`(version_id, org_id, account_id)`。

保存规则：只能写入版本树快照中的叶子组织和叶子科目；零金额不保存，改为零即删除；只能修改 `draft` 状态版本；后端按科目类型转换方向。

汇总单元格（组织或科目至少一侧非叶子）的纯批注存放在伴随表 `budget_cell_note(version_id, org_id, account_id, note)`，只保存文本，不带金额、数量和公式，不参与任何汇总与指标计算。叶子 × 叶子的附注仍随 `budget_entry.note` 保存，写入伴随表会被后端拒绝，两张表的键空间因此互不重叠。保存接口的 `cellNotes` 参数为整包替换语义：不传表示不改动（导入、助手、财务转换链路不受影响），传数组则同事务全量比对替换并推进版本修订号。复制版本时携带汇总批注：同年复制全带；跨年生成按目标树快照过滤，成员已不存在或已退化为叶子 × 叶子的组合被跳过并记录日志。清空版本、删除版本均级联清理；编制记录点把汇总批注与明细一起纳入前后值对比。

## 6. 实际年度状态表 `actual_year_state`

| 字段 | 类型 | 说明 |
|---|---|---|
| year | INTEGER PK | 年度 |
| status | TEXT | open / frozen |
| current_batch_id | INTEGER | 当前最新实际快照 |
| final_batch_id | INTEGER | 年度关闭时的最终快照，可空 |
| frozen_at | TEXT | 冻结时间 |
| updated_at | TEXT | 更新时间 |

规则：`open` 允许更新当前实际；`frozen` 禁止直接更新；重新打开年度须填写原因并记录日志；重开后 `final_batch_id` 保留，后续重新关闭时覆盖。

## 7. 当前实际表 `actual_current`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| year | INTEGER | 年度 |
| org_id | INTEGER | 叶子组织 |
| account_id | INTEGER | 叶子科目 |
| cumulative_amount_cents | INTEGER | 当前累计实际，带符号 |
| quantity | INTEGER | 数量型累计值，按 10^4 缩放；金额科目为空 |
| source | TEXT | manual / excel_import |
| memo | TEXT | 备注 |
| updated_at | TEXT | 更新时间 |

唯一约束：`(year, org_id, account_id)`。

规则：仅保存年度当前最新累计值；年度必须处于 `open` 状态；金额和数量均为零时不保存；更新与快照生成必须在同一事务中完成。组织、科目被停用后，已有行通常保留并继续参与汇总（见五.3）。预算单元格可因公式或附注保留零金额记录。

实际数的汇总单元格批注存放在伴随表 `actual_cell_note(year, org_id, account_id, memo)`，与预算侧同规则：只收非叶子组合、随保存整包替换、不参与汇总。它是对当前年度的批注，不写入快照批次，不随历史修订保留；历史补录模式拒绝携带汇总批注；年度冻结后不可修改。

## 8. 实际快照批次表 `actual_snapshot_batch`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 批次主键 |
| year | INTEGER | 年度 |
| snapshot_date | TEXT | 数据截止日期 |
| revision | INTEGER | 同日修订序号 |
| status | TEXT | active / superseded |
| source | TEXT | manual / excel_import / history_import |
| org_tree_snapshot_id | INTEGER | 组织树快照 |
| account_tree_snapshot_id | INTEGER | 科目树快照 |
| updates_current | INTEGER | 是否更新了当前实际 |
| note | TEXT | 备注 |
| import_batch_id | INTEGER | 关联导入批次，可空 |
| created_at | TEXT | 创建时间 |

规则：同年度同日只允许一个 `active` 快照；同日重新保存生成新修订，原快照标记 `superseded`，不物理删除；`history_import` 不更新 `actual_current`；正常更新不允许使用早于当前截止日期的日期。

## 9. 实际快照明细表 `actual_snapshot_entry`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| batch_id | INTEGER | 快照批次 |
| org_id | INTEGER | 叶子组织 |
| account_id | INTEGER | 叶子科目 |
| cumulative_amount_cents | INTEGER | 截止快照日累计金额 |
| quantity | INTEGER | 截止快照日累计数量，按 10^4 缩放 |

唯一约束：`(batch_id, org_id, account_id)`。稀疏存储：非零值保存，未保存组合按零处理；每个快照是该年度完整逻辑状态。

## 10. 报表指标表 `report_metric`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| code | TEXT | 指标编码，唯一 |
| name | TEXT | 指标名称 |
| display_order | INTEGER | 显示顺序 |
| status | TEXT | active / inactive |
| kind | TEXT | linear（金额）/ ratio（比率），V23 起 |
| direction | TEXT | higher_better / lower_better，仅比率使用 |
| display_format | TEXT | percent / number，仅比率使用 |
| unit | TEXT | 比率的自然单位（percent 时为空） |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

**金额型指标（`kind='linear'`）** 均为利润方向（越大越有利），不使用 direction 字段。示例：毛利、营业利润、利润总额、净利润。

**比率型指标（`kind='ratio'`，V23 起）** 是分子 ÷ 分母。示例：营业利润率、管理费用率、平均上网电价、度电营业成本。口径规则：

- **值的单位与金额指标不同**：比率是按 $10^6$ 缩放的定点整数（`RATIO_SCALE`），金额指标是"分"。两者分别存放在 `RollupResult.metricRatios` 与 `RollupResult.metrics`，报表层也分成 `ratioMetrics` 与 `metrics` 两个字段输出，禁止混列。
- **不可加总**：集团比率 ≠ 各组织比率之和，也不是简单平均。任何汇总行、任何筛选范围都由后端"先汇总分子分母，再相除"重算。
- **预实对比是百分点差**，不是完成率：毛利率预算 30%、实际 25% 记作"低 5 个百分点"，不记作"完成率 83%"。因此比率不套用 `CompletionCell` 的 rate 语义，也不参与年内完成率趋势（比率没有"年初至今累计"含义，与均匀自然日进度不可比）。
- **有利方向必须显式声明**：费用率越低越好、毛利率越高越好，`favorable` 判断读 `direction`，不能沿用"差异为正即有利"。
- **分母为 0 或缺失时值为 `null`**，界面显示 `N/A`，不伪造 0。
- **除法用 BigInt 精确完成**：金额分值乘 $10^6$ 会超出 JavaScript 安全整数范围（约 9007 万元即溢出），浮点除法还会让同一组数在不同路径上出现末位差异。
- **比率是终端节点**：不能被任何指标引用（既不能被金额指标相加，也不能充当另一个比率的分子分母），不参与利润表小计行，不作为财务实际数转换的利润表勾稽目标。
- **数量科目作为比率的任一侧时必须 `quantity_agg='sum'`**：单价、税率等不可汇总的数量科目没有合法的范围合计值。

# 五、组织与科目管理

## 1. 组织管理

支持：新增根组织和下级组织、修改名称、调整排序、移动节点、停用和启用、展开折叠和路径查询、结构检查。

移动节点时检查：目标父节点不是自身及其后代；不破坏已有预算版本的引用（结构引用以快照为准，移动只影响之后创建的版本）。已被业务数据（预算明细、实际明细、快照、汇总格批注）引用的组织不得物理删除。

## 2. 科目管理

支持：建立收入、成本、费用科目树，新增下级、修改名称、调整排序、移动节点、停用和启用、查看完整路径。移动时新父节点类型必须一致。

存在预算或实际明细的叶子科目不能直接增加子科目；需要调整时，新建科目并停用旧科目。科目被业务数据（预算明细、实际明细、快照、指标、汇总格批注）引用后不得物理删除。

## 3. 停用的明确语义（新增明确规则）

组织或科目停用后：

- 已有预算明细、实际数据、快照全部保留，继续参与汇总；
- 树快照保存停用节点（status=inactive），历史口径完整；
- 预算编制界面默认隐藏停用叶子，不允许可见性混乱；
- 实际数维护允许继续修改停用节点的存量行（用于更正累计数）；
- 停用只影响"新增引用"，不清理存量数据。

例外：V9 是一次性数据清理迁移，明确删除已废弃的 `I1102`、`Q102` 科目及其相关明细；这不改变普通停用节点的保留规则。

## 4. 结构变更影响范围

主数据变更只影响：之后创建的预算版本、之后生成的实际快照、未关闭年度的实时汇总。

不影响：已创建版本绑定的树结构、已锁定版本、已生成快照、已关闭年度的历史报表。

# 六、预算版本与编制

## 1. 版本状态机

```text
draft → locked → archived
```

界面将 `locked` 称为“定稿”。“已保存”不是第三种版本状态，而是草稿内的不可变编制记录点。不允许 `locked → draft`、`archived → draft`，修订一律基于定稿版复制新草稿。`kind=budget/forecast` 只表示用途，二者共用状态机、明细表和树快照，不另建预测子系统。

## 2. 草稿版本

允许：编辑明细、批量粘贴、Excel 导入、清空数据、删除整个版本、改名和备注、执行完整性检查、生成编制记录点、定稿。创建时可从历史预算或当前实际按固定增长率生成；生成前返回来源、有效/跳过条数和净额前后值，不存在合适来源时明确报错，不静默创建空稿。录入约 1.3 秒防抖后自动整包保存，自动保存不生成操作日志。

## 3. 定稿与当前生效

定稿前由服务端生成质量报告：检查组织科目引用合法、无非叶子数据、无超范围金额、树快照完整、指标公式无循环，以及快照中配置的必填值、测算依据和测算模板引用/输出情况。问题分阻断项与提醒项；阻断项未清零时不能定稿。定稿在单个事务中完成最终校验、自动补记尚未记录的变化、置状态和写日志，不能靠前端绕过。

每年度、每种版本类型只有一个当前生效版本，只有 `locked` 版本可设为当前生效。预算与预测互不挤占，切换在同一事务中取消原同类版本、设置新版本、写日志。

## 4. 编制界面

当前使用 React + Ant Design 自研二维表格实现编辑矩阵：

- 行：科目/指标（约 200 个科目，按预设表和组织范围过滤）；
- 列：多级组织架构（总汇总、板块小计、叶子组织）；
- 行标题：科目编码、名称、类型/单位；列标题：组织编码、名称、层级；
- 叶子科目 × 叶子组织数据区可编辑，汇总行和汇总列只读并实时计算；
- 支持公式、附注、批量粘贴、冻结、筛选及组织/科目折叠展开；
- 所有单元格（含汇总行、汇总列）均可添加备注；汇总格备注仅作批注，不影响下属明细的数值汇总；
- 利润表按 15 行模板展示指标计算行和科目取数行。

筛选：按组织子树、组织编码/名称搜索、科目类型、科目子树、仅看非零。

## 5. 自动保存与编制记录

矩阵仅约 4 000 单元格，前端跟踪脏单元格用于自动保存状态和离页保护，但保存协议仍整包提交全部非零值；后端在事务内全量比对替换（删除不在集合中的旧记录、upsert 集合内记录）。保存请求在前端严格串行，避免旧请求覆盖新请求：

```json
{
  "versionId": 12,
  "entries": [
    { "orgId": 101, "accountId": 2001, "amount": "123456.78" }
  ]
}
```

后端逐条执行：版本为草稿、组织科目属于版本树快照、二者均为叶子、金额字符串转分、按科目类型转符号、零值删除、非零 upsert。自动保存只更新明细和版本更新时间，不写 `budget.save` 日志。请求可同时携带 `cellNotes` 数组提交汇总格批注（见四.5），与明细同一事务整包替换并推进修订号；不传则保持既有批注不变。

用户在预算讨论节点点击“记录本轮修改”（Ctrl+S），系统先等待草稿自动保存，再把当前快照与上一个记录点比较，记录金额、数量、公式和附注变化；没有变化时不生成空记录。定稿时使用同一机制自动补齐尚未记录的变化。

Excel 确认导入属于互斥写操作：前端先暂停网格编辑、取消尚未触发的防抖任务并等待在途保存结束，导入后回读服务器矩阵并重置本地基线，之后才恢复自动保存。定稿从首次冲刷草稿、校验到确认结束全程暂停编辑，并在最终确认时再次等待最新草稿保存完成，确保定稿版本包含确认前的全部有效录入。

## 6. 固定测算模板

测算只提供“数量 × 单价 ÷ 含税系数”和“两项相乘”两种固定类型。模板按科目编码配置输入和输出，后端使用缩放整数/大整数精确试算，并按组织业务适用范围跳过不适用的输出科目；前端展示预览后把结果写入原预算网格，因此继续受现有自动保存、撤销和定稿质量检查约束。系统不接受任意 JavaScript、SQL 或自定义表达式，不发展为通用计算平台。

# 七、实际数管理

## 1. 当前累计实际录入

界面与预算编制使用同一套科目/组织口径，默认按「行 = 科目/指标，列 = 多级组织」展示；支持「多年趋势对比」与「多组织横向展开」两种视图。叶子组织的叶子科目单元格可编辑，汇总行和汇总列只读。所有单元格均可添加备注：叶子格的备注随明细保存并进快照，汇总格的备注仅作当年批注（见四.7），不进快照、不参与历史补录。输入截止指定日期的**本年累计金额或数量**，不保存本月发生额，不自动累加，用户输入的是新的累计结果。

界面顶部固定显示当前数据年度和截止日期。

## 2. 保存事务

以下步骤在单个事务中完成，任一步失败全部回滚：

1. 年度状态为 `open`；
2. 截止日期属于该年度且不早于当前最新截止日期；
3. 更新 `actual_current`；
4. 读取该年度全部当前非零实际；
5. 生成组织树、科目树快照（内容不变则复用）；
6. 创建新快照批次并全量写入明细；
7. 同日旧快照标记 `superseded`；
8. 更新年度当前快照；
9. 写操作日志。

## 3. Excel 导入

模板支持两种格式：传统扁平模板字段为年度、截止日期（必填）、组织编码、科目编码、累计金额（元，两位小数）/累计数量、备注；结构化模板按年度、组织和预设表生成工作表，金额填报列为万元、数量按科目单位填报。金额和数量二选一，科目编码与组织编码必填。

校验：年度和日期一致；编码存在且有效；组织和科目均为叶子；金额或数量格式正确；同文件组合不重复；年度未冻结；日期不倒退；单文件不超过 5 000 行。结构化模板中的指标行和汇总行只读，不作为明细写入。

所有错误一次性返回（行号 + 字段 + 原因），存在任何错误则整包不写入。全部通过后保存原文件、内容 SHA-256、已校验载荷和摘要，形成待确认批次；确认同一批次后才原子写入并生成快照，不要求再次上传和解析。

普通实际导入记录受影响单元格的写入前后状态。只有这些单元格未被后续修改时才允许自动撤销，撤销通过生成新的实际快照修订完成，不删除既有快照。历史补录不提供自动撤销。

## 4. 历史快照补录

补录允许指定任意历史截止日期，默认不更新 `actual_current`；树口径使用**导入时的当前树结构**并记录绑定（不提供选择历史树的选项，如需按历史口径补录，先确认当前结构未变）。同日重复导入生成新修订并替代旧快照，所有修订保留。

# 八、汇总与指标计算

## 1. 汇总算法

一次性加载树和叶子明细，构建映射：

```text
leaf_org_id → 组织祖先节点集合
leaf_account_id → 科目祖先节点集合
```

每条叶子明细金额同时累计到"组织祖先 × 科目祖先"的全部组合，按带符号整数直接求和，不做二次方向转换。

预算与实际使用同一套计算规则，仅数据来源不同：

| 报表场景 | 明细来源 | 树口径 |
|---|---|---|
| 锁定预算版本 | budget_entry（不可变） | 版本绑定的树快照 |
| 草稿预算版本 | budget_entry | 版本绑定的树快照 |
| 预测版本 | budget_entry（按版本状态） | 版本绑定的树快照 |
| 未关闭年度实际 | actual_current | 当前树 |
| 历史时点实际 | actual_snapshot_entry | 快照绑定的树 |
| 已关闭年度实际 | 最终快照明细 | 最终快照绑定的树 |

## 2. 空值和零值

数据库不存在的明细视为零；报表查询时缺失值补零；金额字段不用 `NULL` 表示零。

## 3. 指标计算

指标在科目汇总完成后按公式拓扑序计算，支持嵌套（如净利润引用毛利），保存时做循环检测。指标与科目汇总共用同一带符号口径。

## 4. 单元测试重点

金额字符串转分；三类科目符号转换；反向金额；树循环检测；叶子检测；多级交叉汇总；指标嵌套与循环；零金额与空数据；停用节点参与汇总。

# 九、分析报表

## 1. 预算完成情况表

可选条件：年度、预算版本、同年度预测版本、实际快照日期、组织范围、科目范围、汇总层级。

| 字段 | 说明 |
|---|---|
| 年度预算 | 选定预算版本金额 |
| 累计实际 | 截止快照日期累计实际 |
| 全年预测 | 可选预测版本金额 |
| 预测较预算 | 预测减预算的利润方向差异 |
| 预算差异 | 实际减预算的利润方向差异 |
| 完成率 | 实际业务金额除以预算业务金额（展示口径） |
| 时间进度 | 均匀自然日进度 |
| 进度偏差 | 完成率减时间进度 |
| 有利/不利 | 按差异符号判断 |

报表顶部固定显示：预算版本、实际数据截至日期、时间进度口径、组织/科目树口径来源。**注意 UI 标注**：差异列为带符号利润方向口径，完成率为无符号展示口径，两者并存须有口径说明。

预算、实际和预测金额可直接打开来源抽屉，查看对应版本/快照、组织科目、下级组成、叶子公式和测算依据、匹配的固定测算参数及关联导入批次。追溯范围刻意限定为直接业务来源，不建设通用证据图谱。

## 2. 差异定义

`V = A - B`（A = 带符号实际，B = 带符号预算）。V>0 有利，V<0 不利，V=0 无差异。成本类科目成本低于预算时 V 为正、判为有利，符合直觉。界面可另展示业务口径差额（收入：实际−预算；成本费用：实际支出−预算支出）。

## 3. 完成率

`R = 实际展示金额 / 预算展示金额`。预算为 0 显示 `N/A`；预算小于 0 显示 `N/A` 并标记特殊预算；实际与预算方向相反时显示异常提示；结果可超过 100%。

## 4. 时间进度

仅均匀自然日进度：`T = 年度已过去天数 / 年度总天数`。报表注明：时间进度仅用于执行节奏分析，不代表月度预算。

## 5. 进度偏差

`P = R - T`。收入和利润指标：正数通常有利；成本费用：正数表示发生偏快，通常不利。

## 6. 历年预实对比

展示多个已冻结年度的：年度预算、年度实际、金额差异、完成率、同比增长、预算版本名称、实际最终快照日期。历史年度一律读最终快照，不按当前树重算。

## 7. 年内完成率趋势

按实际快照日期展示 `R_t = A_t / B` 曲线，叠加均匀进度曲线和超前/滞后区域标注。

## 8. 预算版本对比

同年度两个版本比较：金额变化、变化率、新增/停用组织和科目、树口径差异提示。两版本树快照不一致时，叶子数据按稳定组织/科目 ID 对齐，新增组合原版本按零处理，汇总使用目标版本树结构，报表明示"两版本结构口径不同"。

## 9. 预算准确率

年度冻结后：偏差率 `E = |A - B| / |B|`，准确率 `Q = max(0, 1 - E)`，预算为零显示 `N/A`。同时保留完成率，避免单一准确率掩盖超支/未完成方向。

## 10. 结构占比（共同比报表）

每个科目节点的子树合计 ÷ 基准 = 该节点在基准中的占比，预算与实际各算一遍。基准三选一：

- `parent`：占直接上级科目（看构成，如各明细成本占营业成本）；顶层科目与上级不在筛选范围内的科目显示 `N/A`；
- `account`：全表统一占某个科目子树（共同比报表，如各项占营业收入）；
- `metric`：全表统一占某个金额型指标（如占营业总收入 P01）。

口径与比率型指标一致（见方案四.10）：

- **符号归一**：分子与基准各自乘 `signOfType` 后相除，因此"营业成本占营业收入"读作正的 13.38% 而非 −13.38%；
- **基准非正即 `N/A`**：基准为 0 标记 `na_zero_basis`，归一后为负（如亏损年度拿毛利当基准）标记 `na_negative_basis`，不伪造 0；
- **差异是结构百分点差**（实际占比 − 预算占比），不是完成率，界面不着红绿——结构变化本身无好坏之分；
- **占比不可跨行相加**，唯一例外是同一上级下的各子项；
- **数量科目不参与**（金额恒为 0，占比无意义），也不能作为基准；比率型指标同样不能作为基准；
- **基准必须落在当前筛选范围内**，否则基准合计只含范围内叶子，占比会大于 100% 且无法解释，接口直接拒绝。

**同上级子项守恒核对**：汇总沿科目祖先链累计，因此同一上级下各子项金额之和必然逐分等于上级合计（即使筛选排除了部分子科目，上级也只累计范围内的叶子）。报表把它算出来当断言，`amountReconciled` 为 false 即汇总链路有缺陷。各子项"占上级"比重之和理论为 100%，实际可能相差百万分之几，那是每行独立四舍五入的正常结果，不是错账。

# 十二、Excel 导入与导出

## 1. 导入原则

下载系统生成的标准模板；按组织编码和科目编码匹配（不以名称匹配）；金额最多两位小数、数量最多四位小数；支持传统扁平模板和按组织/年度/预设表生成的结构化模板；错误一次性返回。校验通过后先建立持久预览批次，保存原文件、SHA-256 和解析摘要；用户确认同一批次后原子写入并生成快照和日志。

预算导入只覆盖文件明确包含的单元格，不清空草稿内无关数据。已确认的预算/普通实际批次在相关单元格未发生后续变化时可安全撤销；实际撤销新增快照修订而不改写历史。数据管理页可查看批次状态、下载原文件和执行适用的取消/撤销操作。

## 2. 导出内容

exceljs 生成：预算编制明细、当前累计实际、预算完成情况、历年预实对比、版本对比、实际快照数据、操作日志。

导出文件头部包含：报表名称、年度、预算版本、实际截止日期、组织/科目口径、生成时间、金额单位、数据说明。

# 十三、备份与恢复

## 1. 自动备份

使用 better-sqlite3 backup API 或 `VACUUM INTO`，不直接复制使用中的数据库文件。

策略：每天自动备份一次；重大操作前（迁移、批量历史导入、年度重开、恢复）自动备份；保留最近 30 份日备 + 每月 1 份长期归档保留 24 份；备份目录可配置；文件名含日期时间，如 `budget-backup-2026-06-30-230000.sqlite`。

## 2. 恢复流程

检查备份文件格式 → 对备份执行 `integrity_check` → 自动备份当前库 → 停止写入 → 替换数据库 → 完整性检查 → 重启应用。恢复需二次确认。

# 十四、部署与安全

```text
React 前端 → 本机 Node.js 服务 → 本机 SQLite
```

服务默认只监听 `127.0.0.1`，不暴露局域网和公网；如需公网访问必须显式配置 `BUDGET_HOST=0.0.0.0`，并设置 `BUDGET_ACCESS_USER`、`BUDGET_ACCESS_PASSWORD`。仅在可信本机环境可显式设置 `BUDGET_DISABLE_AUTH=1`。所有 SQL 参数绑定；禁止执行用户提供的公式代码；限制上传文件大小和扩展名；已校验的导入原文件作为批次依据保存在 SQLite 中并随数据库备份；恢复和年度重开需二次确认。本轮规划增强不调整认证或部署安全机制。
