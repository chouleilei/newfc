# 预算系统 AI 助手完整方案

## 1. 目标与范围

为个人使用的预算管理系统增加一个 AI 助手，同时覆盖：

1. **辅助操作**：自然语言查询、导航、导入问题解释、导出和受控批量操作。
2. **辅助编制**：预算草案、历史基准、增长规则、情景测算、异常检查、测算依据。
3. **辅助分析**：预算执行、差异归因、趋势、准确性、异常和自然语言报告。

AI 是“副驾驶”，不是新的记账系统。金额、汇总、快照、版本状态和写入校验仍由现有后端执行。

## 2. 个人项目的设计取舍

不引入以下内容：

- 微服务、消息队列、独立数仓；
- 多用户角色、审批流和复杂权限；
- 向量数据库和大规模 RAG；
- AI 自己维护一套预算数据；
- 自动定时批量修改预算。

采用单体后端中的 `assistant` 模块、SQLite 少量新表、一个可切换的模型适配器即可。模型调用在数据库事务之外完成，写入时只开启短事务。

## 3. 总体交互原则

```text
用户问题
  ↓
识别意图并读取当前页面上下文
  ↓
调用只读工具或生成操作草案
  ↓
后端计算事实、金额和差异
  ↓
AI 组织解释/建议
  ↓
涉及写入时展示预览，用户确认后调用正式业务 API
```

所有回答分为三类：

- **事实**：后端查询得到，显示年度、版本、快照日期和来源；
- **建议**：AI 生成，必须标记为建议；
- **操作**：先预览，确认后执行。

## 4. 功能设计

### 4.1 辅助操作

- 页面导航：打开预算版本、实际录入、执行分析、组织树、科目树等页面；
- 条件查询：按年度、组织、科目、版本、截止日期筛选；
- 业务解释：解释字段、状态、金额方向、万元/元/分转换和完成率；
- 导入辅助：解释错误、建议组织/科目匹配、列出未匹配和重复项；
- 导出：生成指定条件的 Excel/CSV 导出请求；
- 受控操作：复制预算、批量调整、记录编制说明。所有写操作都返回预览并要求确认。

示例：

> “把 2025 年 V2 的费用预算复制成 2026 年草案，整体增长 5%，先给我看变化最大的 20 项。”

### 4.2 辅助编制

#### 预算草案

支持以以下数据为基准：上一版预算、历史锁定预算、当前实际、指定历史快照。用户可以设置收入、成本、费用和数量科目的规则。

规则以结构化参数保存，例如：

```json
{
  "base": "actual_snapshot:2025-12-31",
  "incomeGrowth": 0.08,
  "costGrowth": 0.05,
  "expenseGrowth": 0.05,
  "rounding": "wan_2"
}
```

后端生成每个叶子组织×叶子科目的建议值，并返回：原值、建议值、变化额、变化率、来源和原因。父节点由现有汇总逻辑计算，数量科目不进入金额汇总。

#### 异常与质量检查

- 同比/环比增长超过阈值；
- 历史有实际但预算为零；
- 预算有值但长期没有实际；
- 同类组织或科目明显偏离；
- 数量变化与金额变化不一致；
- 必填科目或测算依据缺失；
- 收入、成本、费用和利润目标不匹配。

#### 情景测算

支持保守、基准、进取，以及自然语言参数（收入下降、成本上升、人员变化、目标利润反推费用上限）。后端执行计算，AI 只负责把自然语言转换为参数并解释结果。

#### 测算依据

AI 可根据已存在的历史数据和用户提供的事实生成依据初稿，但不得编造合同、人数、价格等事实；生成内容标记为“AI 草稿”。

### 4.3 辅助分析

- 预算与实际差异：金额、完成率、贡献组织和科目；
- 差异归因：按组织、科目和方向排序，支持逐层展开；
- 趋势：多年度实际快照、预算准确性和滚动变化；
- 异常：突增、突降、零值、异常完成率；
- 情景分析：改变收入/成本/费用参数后的利润影响；
- 报告生成：执行月报、年度复盘、预算讨论材料。

分析流程必须是“后端先算事实，AI 后写说明”，回答中引用结构化来源，不允许模型自行编造数字。

## 5. 后端实现方案

### 5.1 模块位置

在现有 `backend/src` 下新增：

```text
assistant/
  controller.ts       # 路由处理
  service.ts          # 对话和工具编排
  model.ts            # OpenAI/兼容模型适配
  context.ts          # 当前页面和版本上下文
  tools.ts            # 只读、预览、执行工具
  schemas.ts          # zod/运行时输入输出校验
  prompts.ts          # 系统提示词和任务提示词
  facts.ts            # 结构化事实查询和分析
```

不让模型直接访问 SQLite；工具只能调用现有 service、`rollup`、`money`、快照和报表逻辑。

### 5.2 最小 API 契约

```text
POST /api/assistant/chat
POST /api/assistant/preview
POST /api/assistant/actions/:id/confirm
POST /api/assistant/actions/:id/cancel
GET  /api/assistant/conversations
GET  /api/assistant/conversations/:id
GET  /api/assistant/insights/:id
```

`POST /chat` 请求至少包含：

```json
{
  "conversationId": 12,
  "message": "解释本年度利润低于预算的原因",
  "context": {
    "year": 2026,
    "budgetVersionId": 3,
    "actualSnapshotId": 18,
    "page": "execution"
  }
}
```

回答统一返回 `text`、`facts`、`citations`、`suggestions`、`action` 五类字段。需要流式输出时使用 SSE；结构化结果在结束事件中完整返回。

### 5.3 工具分类

**只读工具**：

- `get_org_tree`、`get_account_tree`；
- `list_budget_versions`、`get_budget_matrix`；
- `get_actual_snapshot`、`list_actual_snapshots`；
- `calculate_execution`、`calculate_variance`、`calculate_trend`；
- `validate_import`、`get_operation_log`；
- `get_cell_notes`：单元格备注查询（预算侧并集明细测算依据与汇总格批注，实际侧为当前累计批注；按组织/科目子树过滤，备注在结果中标记为未核实的录入文本，引用时标注来源）。

**预览工具**：

- `preview_budget_draft`；
- `preview_scenario`；
- `preview_copy_budget`；
- `preview_bulk_adjustment`；
- `preview_basis_text`。

**执行工具**：

- `confirm_budget_draft`；
- `confirm_copy_budget`；
- `confirm_bulk_adjustment`；
- `save_basis_text`；
- `create_export`。

执行工具必须再次检查版本状态、树快照、金额范围和用户确认令牌。

### 5.4 数据表（保持轻量）

建议增加四张表：

- `ai_conversation`：会话标题、创建时间、最近时间；
- `ai_message`：角色、文本、结构化响应 JSON、模型信息；
- `ai_action`：预览参数、差异摘要、状态（pending/confirmed/cancelled/expired）、执行结果；
- `ai_insight`：保存的分析结果、引用快照和生成时间。

不保存完整数据库副本。对话中只保存必要的结构化结果；敏感原始数据不发送给模型时也不落入消息文本。

### 5.5 模型适配

使用一个统一接口：

```ts
interface ChatModel {
  complete(input: ModelInput): Promise<ModelOutput>;
  stream?(input: ModelInput): AsyncIterable<ModelEvent>;
}
```

通过环境变量配置供应商、模型、API 地址和密钥。模型不可用时，查询和确定性分析接口仍应可用；分析文字可以降级为模板化摘要。

### 5.6 提示词和上下文

系统提示词必须明确：

- 不得虚构数据；
- 不得自行计算金额；
- 成本和费用在后端已按负数存储；
- 数量科目不参与金额汇总；
- 历史版本必须使用绑定快照；
- 锁定版本不可修改；
- 不确定时先询问或返回缺少条件。

上下文只传当前任务所需数据，优先传 ID 和工具结果，不把全库内容放入提示词。

## 6. 后端开发顺序

1. 阅读并固化预算规则、金额规则和快照规则；
2. 定义 `assistant` 请求/响应 TypeScript 类型；
3. 实现模型适配器和配置；
4. 实现只读工具及结构化事实查询；
5. 实现 `/chat` 和 SSE 流式接口；
6. 实现预算草案、情景和批量操作预览；
7. 实现确认、取消、过期和审计；
8. 增加四张轻量 AI 表及迁移；
9. 补齐业务护栏测试；
10. 提供前端开发说明、OpenAPI 示例和 mock 数据。

后端完成的标准是：即使没有前端，也可以用 curl 或测试脚本完成查询、预览、确认和取消全流程。

## 7. 测试要求

除普通接口测试外，必须覆盖：

- 元、分、万元转换；
- 收入/成本/费用正负号；
- 数量科目隔离；
- 历史快照和树快照口径；
- 锁定版本不可修改；
- 未确认的 action 不得写入；
- 重复确认不会重复写入；
- 模型返回非法 JSON 或超时；
- 工具查询结果和回答引用一致；
- 批量草案部分异常时不产生半成功写入。

## 8. 给后续前端 AI 的交接内容

后端完成后，应提供：

- API 路由和请求/响应类型；
- SSE 事件格式；
- 所有 action 状态转换；
- 错误码和中文错误信息；
- mock JSON 和最小 curl 示例；
- 金额展示单位说明；
- 预览差异字段说明；
- 页面 context 字段清单。

前端 AI 只负责展示、交互和调用，不实现预算计算、金额转换、版本状态判断或快照逻辑。

## 9. 最终验收标准

- 用户可以自然语言查询预算、实际和执行情况；
- 用户可以生成完整预算草案和情景方案，但未确认前不改数据；
- 用户可以查看差异、趋势、异常和自动分析报告；
- 所有数字可以追溯到预算版本或实际快照；
- 所有写操作有预览、确认、取消和日志；
- 锁定版本、历史快照、金额符号和数量隔离规则不被 AI 绕过；
- 模型更换或暂时不可用不会破坏原有预算系统。

## 10. 实现状态（2026-08）

### 10.1 后端

本方案中的后端任务已落地：`backend/src/assistant` 提供模型适配、上下文解析、意图路由、事实工具、对话编排和预览/确认服务；数据库迁移 V20–V22 创建会话、消息、操作和洞察表并补齐令牌/索引；助手路由已接入现有认证与审计日志。

预算草案支持预算/当前实际/指定历史快照基准并返回逐叶子变化明细；复制支持跨年度和增长率；情景、异常、批量调整、依据草稿和 CSV/XLSX 导出均由后端确定性计算。确认前会校验令牌、过期时间、预览基线、版本状态、树快照和金额/数量规则，失败时事务整体回滚。

辅助操作与辅助分析的其余三项也已确定性实现：

- **差异归因（4.3）**：`assistant/attribution.ts` 以 `completionReport` 为唯一数据源，输出组织与科目两棵逐层展开树（每层按 |差异| 降序取前 `topN`，截断部分以 `hiddenChildCount`/`hiddenVarianceCents` 如实反馈）、父子占比、方向筛选后的叶子贡献榜，并给出两个维度根层/叶子合计的守恒核对；数量科目单独输出，不参与金额归因。入口 `POST /api/assistant/attribution`、只读工具 `calculate_attribution`、洞察类型 `attribution`。
- **报告生成（4.3）**：`assistant/report-draft.ts` 组稿执行月报、年度复盘、预算讨论材料三类报告，章节要点、万元格式化金额与逐节引用全部由后端计算；模型可用时只改写叙述文字（数字、编码、日期与引用不变），不可用或超时则保留模板叙述并标记 `narrativeSource=template`；年度未关闭时不编造准确率与历年对比。入口 `POST /api/assistant/report`、只读工具 `generate_report`、洞察类型 `report`。
- **导入辅助（4.1）**：`assistant/import-help.ts` 把导入校验错误按 17 类固化规则分组并给出含义与处理建议，对未匹配的组织/科目编码基于当前树的编码编辑距离与前缀/名称命中给出候选（候选一定是库中真实节点），并列出重复行与其首次出现行、按严重度排出处理顺序。入口 `POST /api/assistant/import-help`、只读工具 `explain_import`。

接口契约、SSE 事件、curl 示例和 mock 响应分别见 `backend/assistant-openapi.json`、`backend/AI_ASSISTANT.md` 和 `backend/assistant-mock.json`。后端验收测试覆盖金额/数量、符号、快照、锁定版本、幂等确认、模型降级、引用一致性、导出流程，以及归因守恒与截断反馈、三类报告的确定性与降级、导入错误解释与匹配建议（`backend/tests/assistant.test.ts`、`assistant.extensions.test.ts`、`assistant.analysis.test.ts`）。

### 10.2 前端

`frontend/src/pages/Assistant.tsx` 与 `frontend/src/components/assistant/` 提供助手页面：对话与 SSE 流式输出、上下文选择（年度/版本/对比版本/实际快照）、事实与引用面板、建议与导航跳转、操作预览与确认/取消/下载、洞察保存与查看、业务口径抽屉，以及差异归因抽屉（逐层展开树 + 方向筛选 + 守恒提示）、报告生成抽屉（三类报告 + Markdown 成稿 + 逐节引用）、导入辅助抽屉（批次或粘贴错误清单 + 候选建议 + 重复清单）。

页面级 E2E 见 `frontend/tests/e2e/assistant.spec.ts`（4 项 Playwright，覆盖上下文自动解析与「口径」标注、口语化路由、追问延续、写操作预览未确认不落库）。

## 11. 可用性加固（2026-08 第二轮）

首轮实现里确定性计算层已经完备，但「听懂人话」这一层过薄，实际使用时暴露七个问题。本轮逐项修复，原则不变：**数字仍然只由后端算，模型只负责路由与行文**。

### 11.1 意图路由改为模型优先（`assistant/intent.ts`）

原实现由一串正则 `if` 决定调用哪些工具，有三个固有缺陷：关键词重叠导致重复取数、换个说法就漏、宽泛词误判。现在：

- **模型优先**：模型可用时只把一份不含任何金额的上下文摘要（`contextDigest`：年度、版本 ID/名称/状态、快照 ID/日期、已解析的组织与科目、已关闭年度）交给模型，由模型自行调用只读工具，最多 4 轮。
- **正则兜底**：模型不可用、超时或异常时走关键词路由；模型一次工具都没调用时，先用关键词取出事实，再让模型基于这些事实作答，杜绝无事实支撑的自由发挥。
- **语义蕴含去重**：命中报告生成时不再单独跑执行分析、差异归因、异常、质量与趋势；命中差异归因时不再单独跑执行分析。同一份 `completionReport` 不会被算两遍，省略项在 `intents.suppressed` 里如实返回。
- **同义词扩充**：「超支 / 亏得最多 / 拖后腿 / 垫底 / 拉低 / 进度太慢 / 排个名 / 省了 / 结余」等口语说法都能路由。
- **宽泛词收窄**：裸「对比」不再触发版本对比（改为要求「版本对比 / 两个版本 / 与…版本比」等词组）；「为什么」必须跟一个业务判断词，「成本费用为什么是负数」回到业务解释而不是差异归因。

### 11.2 上下文自动解析（`assistant/resolve.ts`）

原实现只接受前端下拉框选好的整数 ID，问「2025 年执行情况」但没手动选版本时只能返回 `missing_context`。现在从自然语言解析：

- **年度**：`2025 年`、裸四位年份，以及「去年 / 今年 / 明年 / 前年」等相对年度；
- **组织与科目**：按名称最长优先匹配（父级不会抢走子级命中），编码匹配要求长度 ≥ 2 且两侧无字母数字，同长度时 active 优先；
- **版本**：按版本名（按出现顺序，第一个作为主版本、第二个作为对比版本）或「版本 3」这样的编号；
- **实际快照**：快照编号、`YYYY-MM-DD`、「截至 6 月」（取该月及之前最新快照）、「最新快照」；
- **导入批次**：「批次 12」、「最近一次导入」。

优先级为 **请求显式传入 > 本轮消息 > 上一轮会话继承 > 数据库默认值**。需要版本才能计算的意图在缺少版本时回退到该年度**当前生效版本**（无当前生效版本时取最新定稿，再取最新版本）；纯列表类问题（如「列出预算版本」）不会被悄悄缩小范围。消息里的年度与前端已选版本冲突时以消息年度为准并换用该年度的版本，而不是抛校验错误。

每一项解析结果都以 `resolution[]` 返回来源（`request` / `message` / `conversation` / `default`）与命中依据，前端逐项展示为「口径」标签，并提供「采用这些筛选」把 `resolvedContext` 回填到筛选器。助手替用户做的每个选择都是可见、可覆盖的。

### 11.3 写操作参数由模型抽取（4.2「AI 只负责把自然语言转换为参数」）

原实现的 `inferAction` 只有 4 条规则且参数大量硬编码（`baseFrom` 恒为 `budget`、`baseYear` 恒为 `year-1`、名称恒为「AI预算草案」），且模型完全不参与。现在：

- **模型抽参优先**：识别到写意图时用专用提示词让模型输出 `{"type","params","reason"}`，只保留每种 action 的白名单字段（`PROPOSAL_FIELDS`），并禁止输出 `bulk_adjustment`（逐格金额只能由用户在表格里给出）。
- **只读干跑校验**：候选参数先经 `normalizePreview` 干跑（该函数只读取数据并计算差异，不写任何业务数据）；构造失败则退回规则推断，两者都失败时返回 `previewable=false` 与 `validationMessage`，由前端引导手动补全。
- **规则兜底也不再硬编码**：基准来源（预算 / 当前实际 / 指定快照）、基准年度与目标年度（同时出现两个年份时较大者为目标）、版本名（支持带引号含空格）、导出类型与格式、情景预设与分类增长率、目标利润都从消息解析。
- **写入路径不变**：`action` 只是建议，落库仍须 `POST /assistant/preview` 生成 pending 预览，再由用户携带确认令牌 confirm。模型没有任何写工具。

### 11.4 SSE 改为真流式

原实现先 `await` 完整回答再按 40 字符切片下发，`model.stream()` 也是 `await complete()` 后一次 yield，首字延迟等于整轮工具调用加生成的总时长。现在：

- 模型适配层实现真正的流式解析：转发 `delta.content` 增量，并按 `index` 累积 `delta.tool_calls` 的参数分片，因此工具调用与正文在同一次请求里边出边解析；
- 控制器先落响应头并发 `event: open`，随后把 `onToken` 回调逐块下发；工具路由轮的正文先缓冲（可能被兜底事实作答覆盖），只有最终作答轮实时转发；
- 未配置模型时确定性摘要也分块下发，前端观感一致；
- 供应商不支持流式（或返回普通 JSON）时按一次性响应解析同一份响应，不重复请求；`AI_STREAM=0` 可强制关闭流式；
- 请求体校验在写响应头之前完成，参数错误仍返回结构化 400；响应头已发出后的异常以 `event: error` 下发并补一个 `event: done`，客户端不会卡在等待 done。

### 11.5 模板模式的回答带真实数字

未配置模型时原来只输出「已查询到 N 组后端事实数据」。现在确定性摘要按事实类型给出可用结论：执行分析给出收入/成本/费用的预算、实际、完成率与时间进度和指标净额；异常检查给出规则数、命中数与按规则代码的分布；质量报告给出问题数与阻断项数；版本列表给出当前生效版本与列表；趋势、版本对比、快照列表、准确率各有对应摘要。金额一律由 `centsToWanText` 按整数分格式化成万元两位小数，不做浮点运算。

### 11.6 多轮追问接得上

会话历史回灌给模型时，助手消息除正文外还附上一轮的**结构化事实有界摘要**（归因保留 `totals` 与前 5 名排行榜，执行分析保留版本、截至日期与指标，异常保留计数与前 5 条，报告保留章节要点，其余截断到 600 字符）。同时上一轮的 `resolvedContext` 作为本轮继承上下文，用户不必每轮重复指定年度和版本。

只回灌上下文与事实还不够：意图识别只看当轮消息，所以模板降级模式下「那第二名呢」一个意图都不命中，会退化成一份版本列表。因此增加**意图继承**（`withInheritedIntents`）：本轮既没有只读意图也没有写意图，且消息带追问标记（「那…」「…呢」「第二名」「再往下拆」「继续」「刚才那个」等）或从消息里解析出了新的组织/科目范围（如「上海公司呢」）时，沿用上一轮的只读意图。

- `report` 继承时改写为 `attribution`：追问通常想看某一块细节，不必重组一份完整报告；
- 写意图不继承只读意图，避免把新的写请求接到旧话题上；
- 继承结果写进响应 `intents.inheritedRead`，界面显示「追问·沿用差异归因」，用户能看出话题是怎么延续的；
- 没有追问标记的新话题（如「你好」）不继承；
- 继承来的意图需要版本而上下文里还没有时，重解析一次补上该年度当前生效版本；
- 模型可用时路由提示词里也会注明「本轮是追问」，要求模型延续上一轮的口径与范围。

配套的一个前端修正：助手页原来把年度预填成当前自然年并持久化，导致句子里的年度（「2027 年执行情况」）被筛选器里的旧值盖掉，多轮追问也无法沿用上一轮的年度。现在助手页不预填年度，缺省年度由后端解析并在「口径」里标注来源；同时只读提问开启 `yearOverride`——句子里**明确写出**的年度（带「年」后缀或相对年度词）覆盖筛选器里的年度并说明替换了什么，裸四位数不参与覆盖，写操作请求一律不覆盖（那里的年份是操作的目标年度，覆盖会把用户选的源版本弄丢）。

### 11.7 配置与工程收尾

- `.env.example` 补齐 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_PROVIDER` / `AI_TIMEOUT_MS` / `AI_STREAM` / `AI_ACTION_TTL_MS`，并说明未配置时助手仍然可用（只是回答文字走模板）。示例文件不含任何真实密钥。
- `get_operation_log` 的入参 schema 从 `additionalProperties: true` 收紧为 `page` / `pageSize` / `action` / `entityType`，`executeTool` 里同步加显式白名单与范围校验，模型无法再往 `queryLogs` 传任意字段。
- OpenAPI 契约补 `ContextResolution`、`ProposedAction` 与 `ChatResponse` 的新字段（含 `model`、`intents.inheritedRead`），mock 增加模型路由与参数建议两个示例响应。
- **路由与降级状态如实展示**：响应新增 `model` 字段（`template` 表示答案来自确定性模板），流式回答也能显示。模型两轮都没产出正文时 `routing` 标为 `rules` 并把原因写进 `modelError`；上游返回的响应既不是 SSE 流也不是合法 completion JSON 时显式报错降级（此前会静默返回空结果，界面显示「模型路由」却拿到模板文案，还会多发一次上游请求）。
- 新增 `backend/tests/assistant.routing.test.ts`（43 项）覆盖：意图去重与同义词、宽泛词不误判、追问信号边界与意图继承、上下文解析各来源与优先级、年度覆盖与写操作不覆盖、编码匹配边界、快照按月份/日期/最新解析、年度与已选版本冲突、模型路由与两级兜底（含空响应与非法响应的显式降级）、模板摘要含真实数字、模型抽参白名单与不可构造退回、禁止提出 `bulk_adjustment`、多轮继承与事实回灌、真流式 SSE 事件顺序与 `delta.tool_calls` 分片拼接、工具入参收紧。后端合计 17 个测试套件、262 项测试全部通过。
- 新增 `frontend/tests/e2e/assistant.spec.ts`（4 项 Playwright）从界面验证：不动任何筛选器提问也能算出数字且「口径」如实标注来源、口语化提问路由到差异归因、追问不重述话题也能延续并收窄范围、写操作参数从原话解析且创建预览后未确认不落库、关闭流式后表现一致。数据自备 2027 年度版本与快照，与财务导入 E2E 互不干扰。
- **真机验证**：用一个 OpenAI 兼容 mock 上游跑通模型路径——`stream: true` 请求、21 个只读工具、分片 `delta.tool_calls` 正确拼成一次工具调用、`delta.content` 按上游节奏逐块转发（首块 ~200ms 到达，不是等完整回答）、模型抽参得到 `source=model` 的可预览参数、追问提示词到达上游；上游超时 / 返回 500 / 返回非法响应三种情况都降级为关键词兜底并写明原因，且只发一次上游请求。

## 12. 全页面回答范围自动对齐（2026-09，AssistantPageContextV2）

前两轮的上下文主要来自 URL 推导与 `/assistant` 页手动筛选，读不到组件内部状态，`page` 字段也没有真正约束取数。本轮按《小澧助手全页面回答范围自动对齐》实施「页面登记 → 发送冻结 → 后端核验合并 → 范围随回答展示」链路，原则不变：**数字与范围事实只由后端确定性服务给出，模型只做意图路由与行文。**

### 12.1 协议：AssistantPageContextV2

提问请求新增可选 `pageContext`（`schemaVersion=2`）：

- `snapshotId`：1–80 字符，用于关联本轮请求和错误定位，不提供幂等去重。
- `pageKey`：28 个页面键，与 `PAGE_CAPABILITY_MAP` 一一对应。
- `routeInstanceId`：1–80 字符，前端用于隔离迟到更新；后端不保存 route 历史或判断实例过期。
- `contextVersion`：非负安全整数。页面语义变化时前端递增；后端当前只校验格式，不比较回退。
- `scope / view / surfaces / focus / selection / draft`：分别表达页面取数范围、白名单视图、浮层链、单一焦点、多选对象和请求内草稿。

大小限制相互独立：除 `draft` 外的 PageContext 按 UTF-8 序列化后不超过 64 KiB；`draft` 不超过 5 MiB；`changes` 不超过 10,000 项；`selection.refs` 不超过 500 项。前端做快速预检，后端按真实字节和 schema 最终裁决。

发送瞬间由前端 `AssistantContextRegistry` 冻结快照；回答过程中页面变化只影响下一轮。旧 `context` 字段保留兼容，携带 V2 时由后端优先采用经过校验的 V2 页面范围。

### 12.2 前端：Registry、页面适配器与范围条

- Registry 拆成稳定 API 与响应式 View，注册、更新和清理由 token + routeInstanceId 保护；路由清理使用 layout effect，避免 SPA 新页面刚登记就被上一页清掉。
- 28 个页面均登记身份与主要范围；页面异步数据未完成或失败时，`buildSnapshot()` 返回 `not_ready`，AssistantProvider 显示 warning 并停止发送。`ready` 状态不进入请求，因此 `CONTEXT_NOT_READY` 是保留码而不是正常 UI 流程的常见服务端响应。
- `AssistantScopeBar` 展示页面名、范围 chips、当前焦点和未保存修改数；发送后以后端 `contextSummary` 为准。
- `/assistant` 页筛选器只属于本页内存状态，不再通过持久化 `manualContext` 覆盖业务页面。
- 草稿序列化器使用稳定代理和 latest ref：语义没变化时不递增 `contextVersion`，发送时仍读取当前渲染状态。

当前生产级深度接线包括预算/实际网格焦点、矩形选区和草稿，Analysis/Structure 的筛选、图表、VerifyBar、EvidenceDrawer，以及首页、指标趋势、历年对比、版本对比的语义图表焦点。协议支持另外六种配置表单草稿，但对应页面尚未全部接入真实未保存表单状态。

### 12.3 后端：统一解析、能力调度与跨年规则

- `assistant/context-v2.ts` 在调用业务工具前完成 schema、大小、view 白名单、资源 ID、年度/版本/快照和树关系校验。页面内部合并顺序为 **最上层 surface > focus > page scope**；selection 当前完成结构、数量和实体校验并随请求保留，但不会通用地自动改写所有查询范围。
- `resolve.ts` 再叠加 **本轮问题明确范围 > 页面范围 > 会话仅补空 > 默认值**。问题明确覆盖页面时返回 `contextStatus=explicit_override` 和 `contextTrace.overrides`，不是一般性 conflict。
- 跨年规则：明确点名另一年度版本时同步切换年度并清除冲突的目标版本/实际快照；裸月份只在当前活动年度内匹配；完整日期、快照编号和“最新快照”等强信号允许跨年。跨年命中快照时年度、快照和同年预算基线原子切换，无同年基线则清除冲突版本。
- 请求自身的 `year` 与预算版本、目标版本或实际快照矛盾时返回 `CONTEXT_CONFLICT`（409）。版本对比要求 `baseVersionId / compareVersionId` 同时存在且属于同一年度。
- `CONTEXT_STALE` 用于焦点归属已不匹配：例如 budget/actual cell 的 sourceId 与当前页面版本/快照不同，或 verification owner 不属于当前 pageKey；不会仅因 `contextVersion` 数字回退触发。
- 页面能力目录限定模型工具和规则意图。普通聊天中不支持的能力通常被过滤并生成 notice，`CAPABILITY_UNAVAILABLE` 保留给直接能力调用，不是所有越界提问的常规响应。

### 12.4 核验事实与草稿隐私

- Analysis、Structure 和 EvidenceDrawer 的领域响应提供 `verificationFacts`，页面 VerifyBar 与助手共用。客户端只传 `ownerKey / factKey` 定位，label、details、level、数量和差额均被忽略并由后端重取。
- 结构小计核验按具体断裂 parentId 与未预算实际承接关系分类；只要仍有一个不可解释父级，整体保持 `bad`，不会被另一个可解释父级错误降级。
- 预算/实际网格草稿在请求内叠加数据库基线，用正式 money、quantity、rollup 和指标服务重算；清空/零值遵循正式整包保存的删除语义。revision、updatedAt、当前批次或树基线变化时报 `DRAFT_STALE`。
- 不保留：原始 `draft.changes`、单元格修改值、`changedCells` 明细。
- 可返回或持久化：`draftApplied.kind / baseline / changeCount / issueCount`，以及 `totalDeltaCents / accountDeltas / metricDeltas / quantityChanges` 等聚合确定性影响。
- 草稿不进入 preview/confirm；正式写入仍必须重新创建预览并由用户携带确认令牌确认。

### 12.5 回答、历史、错误与测试

带 `pageContext` 的回答额外返回：

- `contextStatus`：`aligned` 或 `explicit_override`。
- `effectiveContext`：后端实际采用的安全常用字段子集，不保证回显 scope 中每个扩展资源字段。
- `contextSummary` 和 `contextTrace.used / overrides / warnings`。
- `capability`。
- `draftApplied`：类型、基线、变更数和问题数。

这些安全摘要随 `response_json` 持久化，历史会话显示当时范围；操作日志只记 pageKey、capability、contextStatus 和 draftApplied 摘要。原始草稿、请求头、密钥、文件内容、DOM 和截图不保存。

错误语义：`CONTEXT_INVALID` 用于格式/白名单/资源失败；`CONTEXT_CONFLICT` 用于确定性关系矛盾；`CONTEXT_STALE` 用于焦点归属变化；`CONTEXT_TOO_LARGE` 用于各层上限；`DRAFT_STALE` 用于基线变化。`CONTEXT_NOT_READY` 与 `CAPABILITY_UNAVAILABLE` 是已定义的保留/直接调用码，正常 UI 聊天分别以前端阻断和 notice 为主。

v0.2.3 验证规模：后端 44 个文件 / 651 项，前端 10 个文件 / 127 项，Playwright 11 个 spec / 55 项。数据驱动的 `assistant-pages.spec.ts` 遍历 28 个 pageCase；跨年、版本对比、草稿隐私、核验事实与 Registry 陈旧闭包均有专门回归。
