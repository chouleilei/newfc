## AC-CLR-09 未完成项及复验入口

每一类别须具备匿名原稿/修订稿运行结果、对应文档 SHA-256、正式法审意见 SHA-256、逐项规则及位置标识的期望命中/不命中、建议采纳评价，以及业务复核确认。分别覆盖货物采购、大中型施工、小型基建、技术服务、一般服务、运行维护、收入销售和重大特殊协议。

运行：

```bash
cd backend
node -r ts-node/register/transpile-only scripts/evaluate-contract-legal.ts \
  --paired-manifest /path/to/private/paired-manifest.json \
  --output /path/to/private/paired-result.json
```

清单格式由 `modules/contracts/legal-paired-evaluation.ts` 的 `pairedEvaluationManifest` 定义：`schemaVersion: 1`，`pairs[]` 含 `caseId`、`category`、`sampleKind`、`officialOpinionSha256`、`businessReviewConfirmed`、`original` 和 `revised`。两个版本分别含 `run: { documentSha256, findings: [{ code }] }`、`annotationsComplete` 及 `annotations: [{ code, findingKey?, expected, adoption }]`。`adoption` 为 `accepted | partially_accepted | rejected | unreviewed`。

同一规则有多处发现时，运行结果与人工标注须分别提供匿名 `findingKey`，禁止折叠后把局部检出当全量命中。工具只输出匿名编号、摘要与逐项统计的 TP/FP/FN、未标注发现和建议采纳数量，不读取业务库、不调用模型、不自动转正范本。相同文档不能重复凑覆盖；合成样本、缺意见、未完成标注或未评价建议不能计作历史类别完成；证据不足或存在红线漏检时退出码为 2。正式意见的真实性与采纳结论仍需业务复核人核实，哈希本身不构成人工认可。
