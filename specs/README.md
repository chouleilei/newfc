## 固定方向

**newfc 独立维护全部业务功能、代码、运行数据与部署。** 初始源码与需求基线见 [来源记录](../docs/source-provenance.md)。采用 TypeScript + Express + SQLite、本地文件、应用内 AI 和 systemd；不引入 Dify/DB-GPT。

## 状态与追踪

- **已确定**：用户确认的项目方向、名称、隔离和技术目标。
- **设计基线**：目前建议采用的接口与实现约束，仍需代码和样本证明可行。
- **待定 OPEN-xx**：未决的具体事项、截止阶段和影响，统一维护在实施任务中。
- **已实现/已验证**：必须附新仓库提交及实际验证证据。26 项功能的已验证场景见 [覆盖矩阵](../docs/coverage-matrix.md)，流程缺口与后续验证见 [功能完成度检查](../docs/function-completeness.md)。

功能 ID 保留已确认的来源追踪键；AC-Fxx 对应功能验收，AC-Xxx 对应跨域验收，T-x 为阶段任务。开发记录至少标明相关功能、任务、验收 ID 和实际差异。来源测试只是场景参考，不是 newfc 的测试通过记录。

维护已有 7 个主题即可；不预建大量空目录、每页模板或平台化流程。初始化源码时保留本目录，按需补充领域细设计。任意缩小已确定的业务范围须显式记录，不能把暂未完成标成不需要。

2026-11-15 独立复核：T-13～T-15 的权限、量纲、修订、草稿及证据缺口修补见 [独立验收报告](../docs/improvement-acceptance-review-2026-11-15.md)。`AC-T15-05 / AC-CLR-09` 的八类合成工程回归与正式历史业务验收分别记录，后者仍待业务输入。
