# AI 与审核规范

状态：T-8 契约已实现、验收并发布（2026-10-03）；现行代码能力按验收记录判断，生产为 T-0～T-8 / V66。业务范围见[需求](requirements.md)，公共授权见[数据契约](data-contracts.md)。

## 统一助手

复用本项目的模型渠道、工具调用、页面上下文、引用和数字校验。每新增业务域，注册调用同源 service 的工具；页面、报告和助手采用同一财务事实。

模型负责意图理解、参数提取与文字表达。正式金额、指标、版本状态与审核规则由后端确定性服务提供。模型故障时，已支持的查询仍返回真实事实或明确的能力限制。

既有操作预览与确认机制继续维护。新增财务写操作默认走业务页面的受控确认流程；如接入助手操作卡片，必须复用服务端预览、状态重检和显式确认，聊天文字不能直接触发写入。

## 单据审核流程

合同与费用审核采用应用内流程：单据/附件 → 解析或 OCR → 确定性规则 → 有来源的制度依据 → 模型语义建议 → 输出校验 → 人工复核。

迁移规则时核实阈值与制度的适用性；原项目内置摘录不自动视为完整正式制度。模型异常、缺附件、识别失败和制度证据不足均明确返回待复核。保留 AI 结果与追加的人工结论，不把兜底当作自动审批成功。

## 领域工具与知识检索

应用采用领域工具和明确参数，不开放任意 SQL。未覆盖的长尾问题必须如实提示能力范围，并在验收中记录差异。

知识检索先采用 SQLite FTS5/关键词索引，验证编译支持、中文分词与召回；扫描件先解析/OCR。文档保存来源、版本/生效期、页码/段落和访问范围，检索时应用权限，更新或删除同步索引。不将全文检索标称为等价语义检索。

凭据、费用控制和调用日志在应用内实现。费用账本持久保存，调用前短事务预占、结束后结算；模型网络请求不持有 SQLite 写事务。不引入独立 AI 网关或工作流中间件。

## 请求与回答要求

1. 使用本项目的页面上下文解析：本轮明确问题范围、已核验页面范围、会话补空和默认值的来源可解释。页面快照/版本引用要由后端核验。
2. 工具参数必须通过 schema 和权限检查；返回状态区分正常、缺失、错误与不可用。无数据不等于业务没有问题。
3. 答案保留本轮事实、引用、有效范围、使用的工具与模型/规则路径。金额单位、符号和差异定义按[数据契约](data-contracts.md)与领域工具说明；提示词和业务解释词典不得把经营预算口径推广到所有领域或重复换算。数字核验是错误提示机制，不能替代财务规则正确性的验收。
4. 文档、附件、数据库文本按不可信数据处理，不能变成可改变系统权限或执行流程的指令。
5. 继承的流式协议先保留并做契约测试；正文中途失败、用户取消和连接断开必须清理模型请求和任务资源，最终状态如实持久化。
6. 写意图只能生成已有业务流程的建议或受控预览；费用复核、合同审批、发布等正式动作仍由具备权限的显式操作完成。

## 全领域只读问答契约（F20，AC-X04/X06）

助手保留经营预算分析，并覆盖 EAS、财报与趋势、管理会计、项目预算、计划执行、合同与付款、报销审核与制度依据、可研、投资控制、财务预测、风险与整改、分析报告、标准报表、治理、项目全景与主数据、检索、后台任务、配置和授权范围。新增工具只读取同源领域 service 的结果；测算、扫描、付款、复核、审批、发布等正式动作由业务页面显式执行。

- 页面能力目录维护路由、权限、可读工具和 view 白名单。当前页签、筛选、对象详情与来源批次进入页面上下文；离开页面或切换页签时清理旧注册，不能沿用另一领域对象。助手首页提供按权限显示的业务提问入口。
- 项目、合同、报销、可研项目/方案、投资项目/快照、预测模型/版本/运行、风险、报告、来源批次和任务分别使用独立 ID 字段，不能借用经营预算版本或实际快照 ID。服务端核验存在性、领域权限、组织可见性和对象关联，名称歧义先澄清，无命中不能返回其他对象的金额。
- 新领域月份使用 `period`（YYYY 或 YYYY-MM），趋势使用 `periodFrom`/`periodTo`，财报使用 `statementScope`；继承协议的 `periodStart`/`periodEnd` 仍为日期。指定历史批次时，期间和年度取自授权来源，显式冲突拒绝，不替换为当前生效批次。引用链接定位实际来源详情。
- 模型遗漏已核验的对象、组织、期间或年度时，服务端为相应工具补齐；模型参数与本轮范围冲突时拒绝。台账筛选、管理会计所选指标/期间/分组以及页签记录过滤按对应工具保留，不能用无筛选汇总冒充当前筛选结果。
- 模型不可用或调用工具全部失败时，支持的领域查询返回真实规则结果，保留事实、引用、降级原因和范围。缺来源、缺参数、无记录、无权限及查询失败分别表达；没有数据不补零，也不视为审核通过。
- 新领域金额按十进制字符串原样传递，数量与比率依各自单位说明；不套用经营预算万元口径。列表有界，截断明确提示，不把展示行的金额当作全库汇总。
- 报销解释只引用当前有效审核运行，不发送申请人或附件正文；配置概览不包含凭据、地址或集成参数；分析报告采用已发布/已替代或本人报告的助手可读范围。
- 制度工具提供有版本与条款来源的关键词匹配，当前不承诺语义召回或扫描件全文检索。任意 SQL、聊天直接写入、真实供应商输出等价性均不在此只读问答契约内；外部能力须单独联调验收。

## T-8：统一上下文与页面能力契约

本节为 2026-10-02 确认、2026-10-03 完成实施与验收的现行代码契约。统一快照、配置草稿、字段帮助及真实选区已接入；代码证据见 [T-8 阶段验收](../docs/acceptance-records.md#t-84t-86--阶段完成2026-10-03)，生产已发布本阶段，见 [发布记录](../docs/acceptance-records.md#t-8-生产发布2026-10-03)。定义的组织方式在 [架构规范](architecture.md#t-8页面与工具定义的唯一来源现行)维护。

### 唯一请求与解析路径

1. 聊天及流式聊天只接收 `{ conversationId?, message, pageContext }`。共享类型命名为 `AssistantPageContext`，以现有页面快照结构为基础，保留唯一受支持的 `schemaVersion: 2`；此数字用于协议检查，不保留 `V2/Legacy` 双实现。独立助手页也发送 `pageKey: 'assistant'` 的快照，其 scope 可以为空，手动筛选属于该页 scope。
2. `pageContext` 是页面输入的唯一来源；禁止旧顶层 `context`、双传、未知版本以及未登记页面。缺快照或携带旧字段返回 400 `CONTEXT_INVALID`；未知版本返回 409 `CONTEXT_PROTOCOL_UNSUPPORTED`，页面提示刷新并保留问题文本，不自动重试旧协议。请求校验先于模型调用、会话落库和 SSE 响应头。快照过期/对象冲突沿用 `CONTEXT_STALE`/`CONTEXT_CONFLICT`，草稿基线过期用 `DRAFT_STALE`。
3. API schema/前端请求响应类型在 `backend/src/contracts/assistant.ts` 统一维护。后端解析结果命名为 `ResolvedAssistantContext`，统一使用 scope 中的字段语义（如 `orgScopeId`/`accountScopeId`），传入领域 service 时只做该接口必要的 DTO 映射；删除旧 `AssistantContext` 字段别名、`scopeToLegacyContext`、旧协议 normalize/merge 分支和“旧客户端不限制页面能力”路径。
4. 页面快照按“最上层浮层 > 明确焦点 > 页面 scope”确定对象；问题明确范围 > 已核验页面范围 > 上轮仅补空 > 合法默认值。消息与活动选区/草稿目标冲突时先澄清或拒绝，不能用旧对象回答新范围。授权是所有来源共同的硬边界；上轮页面 view、浮层、草稿和选区不能补入新页面。
5. 页面未就绪、登记缺失或未知路由时阻止发送并提供重试/返回有效页面；去掉从 URL 猜旧上下文的发送兜底。路由信息仅负责页面识别/标签，真实查询状态由页面登记。清理回调按 token、路由实例及页签/对象变化生效；保存、取消、关窗、换页签、切对象、退出会话后清除相应草稿/焦点/选区，迟到回调不得清除新状态。
6. 归因、报告草稿和导入辅助入口凡使用页面范围，均消费同一 `pageContext` 和解析器；用户显式选择的操作参数与页面范围需核验冲突，不允许第二条不经核验的上下文捷径。普通业务接口保留自己的领域 DTO。
7. 返回一份 `effectiveContext` 及解释其来源的 `contextTrace`，供范围条、引用和多轮补空使用；移除响应中同义的旧 `resolvedContext`。模型路径与规则路径使用同一已核验范围和事实。

### 本项目已有数据

- newfc 已有业务事实、会话正文、引用、审计、审批与发布记录保留。取消来源项目兼容不授权清库或修改财务口径。
- 本阶段通过追加迁移，一次性规范化 `ai_message.response_json` 中供多轮使用的上下文和范围显示字段；历史消息标识为历史范围，不能伪造当时不存在的页面快照。可确定字段作明确映射，无法确定的范围保留原始历史内容并标记不可续用，下一轮要求明确范围。
- 历史原始响应完整保留在迁移前备份中；在线 JSON 仅规范化上下文元数据，正文、事实与引用不重算。损坏到无法安全转换的 JSON 中止迁移并报告记录 ID，不静默丢弃。新历史读取/追问只使用规范化结果，并检查会话归属与现时授权。格式转换代码限于追加迁移，运行入口不保留 Legacy reader，也不新增长期旧协议档案服务。用临时文件库验证迁移、重复执行和恢复。

### 草稿接入与只读分析

八类既有草稿都必须有实际页面入口；预算/实际网格保持已有功能，并按统一契约回归。新增六类如下，不能只登记数据而没有回答结果：

| 草稿 | 页面与操作 | 必须提供的结果 |
|---|---|---|
| `org_form` | 组织管理的新建、改名、移动、状态操作的实际表单/确认面板 | 编码/层级/循环与引用约束、操作影响说明；遵守当前具体操作允许修改的字段 |
| `account_form` | 科目管理的新建、编辑、移动、状态操作 | 类型、单位、数量汇总方式、表格归属、层级/引用检查；说明已有快照与当前树的区别 |
| `metric_formula` | 指标页线性/比率指标编辑弹窗 | 公式解释、完整依赖图及循环、分子分母/量纲/方向检查；明确受影响的当前指标，不能宣称已重算历史快照 |
| `calculation_rule` | 数据管理“测算模板”的新建/编辑弹窗 | 输入数量/单价/税率与输出科目校验、公式和影响目标说明；提供明确版本时按同源只读计算显示结果，无版本不编造金额 |
| `cleaning_template` | 实际录入/预算编制打开的清洗导入向导，在列与口径、名称映射、差异预览、模板保存步骤 | 工作表/区域/列映射/单位与符号/数量规则解释；结合有效分析或预览说明问题和覆盖影响。清洗配置页仍是已有模板摘要入口 |
| `alias_rule` | 清洗配置别名编辑，以及清洗向导的名称映射/保存别名操作 | 规范化重名与冲突、目标存在性/适用性检查及映射解释，区分当前导入映射与保存为长期别名 |

- 草稿按具体操作携带类型化 base（目标 ID、服务器提供的基线/修订或新建 clientKey）与用户实际变更字段；后端读当前基线后合并校验，不把部分修改中缺失的字段当作空值。基线从同源读取接口取得，不能以客户端自报内容证明有效。
- 完整性限制沿用常规上下文 64 KiB、独立草稿 5 MiB、最多 10,000 项变更；按 UTF-8 实际字节校验。单次普通助手查询/选区分析最多处理 500 个对象，详情返回最多 30 项并说明截断；query 在有权范围内先核对总量，超过 500 要求缩小筛选。公式完整依赖检查可读取所选指标的必要依赖，但不把依赖节点计作用户选中对象，且沿用领域计算的资源上限。
- 从组织、科目、指标、测算、清洗及别名 service 提取可读的规范化/校验/依赖分析函数，正式保存与助手共用；保存仍在短事务内重检。移除 `draft-context.ts` 中六套不完整的平行规则。范围/对象/基线鉴权先于依赖读取，不能先通过错误提示泄露受限对象。
- 草稿分析不插入临时业务记录、不先保存再回滚、不创建树快照/导入批次；可写的只有正常助手会话/审计和模型调用账本。清洗仅引用当前用户有权访问的有效暂存文件/分析/预览，校验所有者、指纹、目标和过期状态；如暂存元数据缺所有者，补齐上传绑定，过期上传要求重新上传。解析复用现有有界读取，模型不能触发重新导入或提交预览。
- `draft_validation`/`draft_impact` 及字段说明在模型路由/最终回答前形成可信事实，正常模型和规则降级都能展示：当前未保存修改、校验错误/提醒、已核实依赖/影响、未能计算的原因。界面能定位回相关字段；“校验通过”只代表本次校验，正式保存仍重新检查。
- 原始网格草稿、文件内容、备注及任意配置 JSON 不进入模型或日志。模型只取得后端生成的有界事实摘要、公式/规则解释和必要脱敏标签；源文件令牌留在服务端处理边界。配置事实补上模型输入之后再验证引用与数字，不允许模型自行计算正式金额。
- 页面沿用现有弹窗、向导和助手面板，用当前对象/未保存提示及“检查当前修改”入口连接；弹窗内须能打开并操作助手，桌面与窄屏不能被遮罩/焦点陷阱挡住。页面状态只登记一次，输入/hover 不触发模型或额外请求，保存仍由原页面显式确认。

### 字段与选区必须影响实际行为

- 六类配置草稿及清洗向导的实际输入字段接入 `form_field`。字段按具体 formKind 白名单定义标签/含义/约束；点击字段帮助或实际 focus 登记，hover 不切焦点，助手获得的是当前字段及后端认可的说明。关闭编辑后失效。
- `bounds`：预算和实际网格已有选区，后台按选中的组织/科目及工作表求交，读取/汇总必须限定这些单元格；稀疏选区不得冒充完整矩形，父子节点同时出现不得重复计入。
- `refs`：指标列表与清洗别名列表提供明确多选入口，按选中 ID 分析依赖/公式或映射冲突；逐对象验权，全部 ID 在 500 上限内校验，不静默截断。取消选择恢复当前页面范围。
- `query`：同一指标/别名列表支持“当前筛选结果”提问，复用页面真实筛选和同源查询，覆盖全部匹配结果而非当前分页；查询键按页面白名单，不接受任意 SQL、模型声明的总数或客户端行数据。超出处理上限提示缩小范围，不能偷偷改成前 N 条的全量结论。
- 支持的选区类型和服务在页面/工具定义中明确关联，工具实际接收并执行选择约束；仅接收快照而忽略选区不算接入。不支持该选区的工具返回 `CAPABILITY_UNAVAILABLE`，页面不展示不可执行的入口。回答显示选择模式、实际范围/数量、截断或不可计算原因。

## 验证样本

至少包括正确范围问答、跨年度追问、越权参数、无数据、模型超时/空正文/非法参数、无知识命中、伪造文档指令及附件识别失败。正常问答核对页面与工具的精确金额及来源；外部 OCR/模型能力验证与规则兜底分别记录。

外部模型/OCR 按 OPEN-05 配置：New API 的 OpenAI 兼容接口、gemini-flash-latest 与 tangdalei 异步 OCR 直连；制度采用首版费用规则（deploy/expense-policy-v1.json），检索使用关键词/FTS。真实供应商与合成单据的验证证据见 docs/acceptance-records.md，不宣称真实业务单据准确率已验证。
