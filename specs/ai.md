# AI 与审核规范

状态：设计基线；继承和新增能力均须在 newfc 验证。业务范围见[需求](requirements.md)，公共授权见[数据契约](data-contracts.md)。

## 统一助手

复用本项目的模型渠道、工具调用、页面上下文、引用和数字校验。每新增业务域，注册调用同源 service 的工具；页面、报告和助手采用同一财务事实。

模型负责意图理解、参数提取与文字表达。正式金额、指标、版本状态与审核规则由后端确定性服务提供。模型故障时，已支持的查询仍返回真实事实或明确的能力限制。

既有操作预览与确认机制继续维护。新增财务写操作默认走业务页面的受控确认流程；如接入助手操作卡片，必须复用服务端预览、状态重检和显式确认，聊天文字不能直接触发写入。

## 单据审核流程

合同与费用审核采用应用内流程：单据/附件 → 解析或 OCR → 确定性规则 → 有来源的制度依据 → 模型语义建议 → 输出校验 → 人工复核。

迁移规则时核实阈值与制度的适用性；原项目内置摘录不自动视为完整正式制度。模型异常、缺附件、识别失败和制度证据不足均明确返回待复核。保留 AI 结果与追加的人工结论，不把兜底当作自动审批成功。

## 领域工具与知识检索

应用采用领域工具和明确参数，不开放任意 SQL。未覆盖的长尾问题必须如实提示能力范围，并在验收中记录差异。

知识检索先采用 SQLite FTS5/关键词索引，验证编译支持、中文分词与召回；扫描件先解析/OCR。文档保存来源、版本/生效期、页码/段落和访问范围，检索时应用权限，更新或删除同步索引。不将全文检索标称为等价语义检索。

凭据、费用控制和调用日志在应用内实现。费用账本持久保存，调用前短事务预占、结束后结算；模型网络请求不持有 SQLite 写事务。不引入独立 AI 网关或工作流中间件。

## 请求与回答要求

1. 使用本项目的页面上下文解析：本轮明确问题范围、已核验页面范围、会话补空和默认值的来源可解释。页面快照/版本引用要由后端核验。
2. 工具参数必须通过 schema 和权限检查；返回状态区分正常、缺失、错误与不可用。无数据不等于业务没有问题。
3. 答案保留本轮事实、引用、有效范围、使用的工具与模型/规则路径。金额单位、符号和差异定义按[数据契约](data-contracts.md)与领域工具说明；提示词和业务解释词典不得把经营预算口径推广到所有领域或重复换算。数字核验是错误提示机制，不能替代财务规则正确性的验收。
4. 文档、附件、数据库文本按不可信数据处理，不能变成可改变系统权限或执行流程的指令。
5. 继承的流式协议先保留并做契约测试；正文中途失败、用户取消和连接断开必须清理模型请求和任务资源，最终状态如实持久化。
6. 写意图只能生成已有业务流程的建议或受控预览；费用复核、合同审批、发布等正式动作仍由具备权限的显式操作完成。

## 全领域只读问答契约（F20，AC-X04/X06）

助手保留经营预算分析，并覆盖 EAS、财报与趋势、管理会计、项目预算、计划执行、合同与付款、报销审核与制度依据、可研、投资控制、财务预测、风险与整改、分析报告、标准报表、治理、项目全景与主数据、检索、后台任务、配置和授权范围。新增工具只读取同源领域 service 的结果；测算、扫描、付款、复核、审批、发布等正式动作由业务页面显式执行。

- 页面能力目录维护路由、权限、可读工具和 view 白名单。当前页签、筛选、对象详情与来源批次进入页面上下文；离开页面或切换页签时清理旧注册，不能沿用另一领域对象。助手首页提供按权限显示的业务提问入口。
- 项目、合同、报销、可研项目/方案、投资项目/快照、预测模型/版本/运行、风险、报告、来源批次和任务分别使用独立 ID 字段，不能借用经营预算版本或实际快照 ID。服务端核验存在性、领域权限、组织可见性和对象关联，名称歧义先澄清，无命中不能返回其他对象的金额。
- 新领域月份使用 `period`（YYYY 或 YYYY-MM），趋势使用 `periodFrom`/`periodTo`，财报使用 `statementScope`；继承协议的 `periodStart`/`periodEnd` 仍为日期。指定历史批次时，期间和年度取自授权来源，显式冲突拒绝，不替换为当前生效批次。引用链接定位实际来源详情。
- 模型遗漏已核验的对象、组织、期间或年度时，服务端为相应工具补齐；模型参数与本轮范围冲突时拒绝。台账筛选、管理会计所选指标/期间/分组以及页签记录过滤按对应工具保留，不能用无筛选汇总冒充当前筛选结果。
- 模型不可用或调用工具全部失败时，支持的领域查询返回真实规则结果，保留事实、引用、降级原因和范围。缺来源、缺参数、无记录、无权限及查询失败分别表达；没有数据不补零，也不视为审核通过。
- 新领域金额按十进制字符串原样传递，数量与比率依各自单位说明；不套用经营预算万元口径。列表有界，截断明确提示，不把展示行的金额当作全库汇总。
- 报销解释只引用当前有效审核运行，不发送申请人或附件正文；配置概览不包含凭据、地址或集成参数；分析报告采用已发布/已替代或本人报告的助手可读范围。
- 制度工具提供有版本与条款来源的关键词匹配，当前不承诺语义召回或扫描件全文检索。任意 SQL、聊天直接写入、真实供应商输出等价性均不在此只读问答契约内；外部能力须单独联调验收。

## 验证样本

至少包括正确范围问答、跨年度追问、越权参数、无数据、模型超时/空正文/非法参数、无知识命中、伪造文档指令及附件识别失败。正常问答核对页面与工具的精确金额及来源；外部 OCR/模型能力验证与规则兜底分别记录。

外部模型/OCR 按 OPEN-05 配置：New API 的 OpenAI 兼容接口、gemini-flash-latest 与 tangdalei 异步 OCR 直连；制度采用首版费用规则（deploy/expense-policy-v1.json），检索使用关键词/FTS。真实供应商与合成单据的验证证据见 docs/acceptance-records.md，不宣称真实业务单据准确率已验证。
