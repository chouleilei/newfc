# AI 与审核规范

状态：设计基线；继承和新增能力均须在 newfc 验证。业务范围见[需求](requirements.md)，公共授权见[数据契约](data-contracts.md)。

## 统一助手

复用 newbd 的模型渠道、工具调用、页面上下文、引用和数字校验。每新增业务域，注册调用同源 service 的工具；页面、报告和助手采用同一财务事实。

模型负责意图理解、参数提取与文字表达。正式金额、指标、版本状态与审核规则由后端确定性服务提供。模型故障时，已支持的查询仍返回真实事实或明确的能力限制。

newbd 原有操作预览与确认机制继续维护。新增财务写操作默认走业务页面的受控确认流程；如接入助手操作卡片，必须复用服务端预览、状态重检和显式确认，聊天文字不能直接触发写入。

## 覆盖 Dify 曾承担的业务

lishui 的合同审核已有本地规则与模型路径，但费用审核还依赖 Dify 附件转交及工作流。新应用实现：单据/附件 → 解析或 OCR → 确定性规则 → 有来源的制度依据 → 模型语义建议 → 输出校验 → 人工复核。

迁移规则时核实阈值与制度的适用性；原项目内置摘录不自动视为完整正式制度。模型异常、缺附件、识别失败和制度证据不足均明确返回待复核。保留 AI 结果与追加的人工结论，不把兜底当作自动审批成功。

## 覆盖 DB-GPT 曾承担的业务

原项目 DB-GPT 主要提供自由 SQL 与知识检索。新应用优先采用领域工具和明确参数，不首期开放任意 SQL。未覆盖的长尾问题必须如实提示能力范围，并在验收中记录差异。

知识检索先采用 SQLite FTS5/关键词索引，验证编译支持、中文分词与召回；扫描件先解析/OCR。文档保存来源、版本/生效期、页码/段落和访问范围，检索时应用权限，更新或删除同步索引。不将全文检索标称为等价语义检索。

原项目网关的凭据、费用控制和调用日志要求在新应用内实现。费用账本持久保存，调用前短事务预占、结束后结算；模型网络请求不持有 SQLite 写事务。新应用不需要先复制再删除 Dify/DB-GPT 或 Python 网关实现。

## 请求与回答要求

1. 优先复用 newbd 的页面上下文解析：本轮明确问题范围、已核验页面范围、会话补空和默认值的来源可解释。页面快照/版本引用要由后端核验。
2. 工具参数必须通过 schema 和权限检查；返回状态区分正常、缺失、错误与不可用。无数据不等于业务没有问题。
3. 答案保留本轮事实、引用、有效范围、使用的工具与模型/规则路径。数字核验是错误提示机制，不能替代财务规则正确性的验收。
4. 文档、附件、数据库文本按不可信数据处理，不能变成可改变系统权限或执行流程的指令。
5. 继承的流式协议先保留并做契约测试；正文中途失败、用户取消和连接断开必须清理模型请求和任务资源，最终状态如实持久化。
6. 写意图只能生成已有业务流程的建议或受控预览；费用复核、合同审批、发布等正式动作仍由具备权限的显式操作完成。

## 验证样本

至少包括正确范围问答、跨年度追问、越权参数、无数据、模型超时/空正文/非法参数、无知识命中、伪造文档指令及附件识别失败。正常问答核对页面与工具的精确金额及来源；外部 OCR/模型能力验证与规则兜底分别记录。

外部模型/OCR 的供应商与协议兼容、制度样本和中文检索效果列为 OPEN-05；未完成验证前，不宣称与旧平台等价。
