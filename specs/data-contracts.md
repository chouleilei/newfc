# 数据、权限与接口契约

状态：现行跨域契约。实现与验收见 [验收记录](../docs/acceptance-records.md)，各领域修改仍须满足本文件不变量。

## 财务与存储不变量

- **金额**：两位小数金额采用整数分，核对 SQLite 有符号 64 位范围与汇总溢出。新领域采用 bigint 定点及 64 位范围，可能超出 2^53 的金额列读取必须 safeIntegers(true)，API 返回十进制字符串；经营预算的 number 金额继续执行安全整数校验，详见 docs/money-contract.md。
- **高精度计算**：数量、比例、单价与现金流分别定义精度，使用 core/decimal.ts 的缩放 bigint、显式 scale 与明确舍入步骤。禁止无条件将所有金融数值转换为 number 或 SQLite REAL。
- **兼容性**：扩大金额范围涉及现有汇总、JSON 与前端格式化，不能只修改一个存储字段。已有限额要显式校验，不允许静默截断。
- **事务**：WAL 允许读写并行，但仍是单写者。临界区使用短事务、必要的 BEGIN IMMEDIATE、条件更新和唯一约束。并发状态转换使用条件更新与状态重检，不能仅凭事务存在就认为业务并发安全。
- **连接与持久性**：开启外键、合理 busy timeout，控制长读事务和 WAL 增长。正式财务写入优先 synchronous=FULL，差异经实测评估；不得降低为 NORMAL。
- **导入**：先做有界解析/暂存和全文件验证，再在短事务中原子写批次与事实。模型、OCR、文件 I/O 和长时间解析放在写事务外。
- **后台任务**：持久保存任务状态，限制并发，重启后按既有幂等规则识别并处理未完成任务。SQLite 同步查询和大 Excel/PDF 任务不能长期占住 Node 主线程。
- **备份**：使用 SQLite 在线备份 API 或受控停写；同时保存文件对象和对应清单，验证库与附件恢复一致性。不能运行中只拷主数据库文件而遗漏 WAL。

内存 SQLite 测试不能替代文件库迁移、精度、外键或并发验证；须使用临时文件 SQLite 和多连接场景验证。

## 数据所有权与关联

| 概念 | 保持的业务语义 | 实施要求 |
|---|---|---|
| 组织/科目 | 当前树与历史树快照分开 | 跨域编码先映射为规范实体；停用/改名不得重算历史 |
| 预算/实际 | 版本、年度、快照与来源批次明确 | 使用经营预算事实层，拒绝年度/版本混用 |
| EAS 原始事实 | 原文件与原始行可追溯 | 映射覆盖层与原始金额分离，更正通过新批次及原子切换 |
| 合同/费用/项目 | 独立生命周期 | 与组织、项目、供应商明确关联，不压入通用科目表 |
| 指标/投资/报告 | 正式结果可复现、冻结 | 保存计算版本、参数/来源快照与口径，不依赖当前默认值重算历史 |
| 文件证据 | 不可变原件和受控访问 | 相同内容可复用对象，业务引用保留自己的权限与生命周期 |

实体 ID 在新库独立生成；实际迁入时保留来源系统/来源 ID 映射，禁止假定两个系统相同数字 ID 代表相同对象。文件对象与数据库提交失败时必须有可恢复的暂存/回收路径，不假定文件系统与 SQLite 组成一个事务。

## 公共请求与金额协议

以下是新建或改造接口的目标契约，继承接口的适配须在实际改变前记录并更新前端，不可将新领域契约无条件套用到继承接口。

| 类型 | 目标语义 |
|---|---|
| money | API 使用精确十进制字符串，字段同时明确币种与单位；前端显示换算不改原值 |
| ratio | API 使用明确精度的 0～1 比率或领域定义的有符号比率；不混用百分数，超范围规则按指标定义 |
| quantity / unit_price | 独立声明单位和小数位；不参与金额汇总 |
| missing | null 表示缺失，0 表示确认的零；不得把解析失败变成 null/0 后继续导入 |
| period | 明确年度、月度和累计/期末，不以字符串外观推断业务口径 |
| scope | 年度、组织、项目、版本/快照引用先核验关系，再与服务端授权范围相交 |
| error | 稳定业务错误码、可展示说明、请求定位 ID；不暴露原始 SQL、凭据或内部异常 |
| page | 台账分页返回 `{ items, total, page, pageSize }`；page/pageSize 为正整数，默认 1/20，pageSize 最大 100；范围/筛选先于 COUNT 和 LIMIT，两次读取使用同一短读事务。超出尾页返回实际尾页，空集返回 page=1/total=0 |

继承的 number 金额首先保留安全整数校验；扩大量程前，必须端到端验证存储读取、汇总、模型上下文、JSON 和前端显示。BigInt 不可直接 JSON.stringify，不能通过 Number() 绕过此限制。具体字段小数位与舍入模式已由 docs/money-contract.md 与领域契约定义；扩大范围前必须端到端验证。

## 认证与授权

- 前端进入会话、登出、会话失效或校验失败时清空业务查询缓存并取消旧查询；迟到响应不得重新进入下一会话的缓存。收藏、最近访问与保存视图按服务端用户 ID 隔离，显示名不参与身份键。
- CSRF 令牌失效时仅允许同一账号、权限、组织范围及强制改密状态下刷新令牌并重试一次；发现身份或授权变化时清会话并要求重新登录，禁止以新账号自动重放旧操作。会话变化后，旧普通响应、下载和助手流不得继续返回数据或使新会话退出。
- 可研报告与预测版本的“本人提交/冻结”由服务端账号 ID 判断，分别通过 `submittedByCurrentUser`、`frozenByCurrentUser` 返回给页面；显示名仅用于展示，同名和改名不得影响复核例外提示。后端继续独立校验同人复核权限与例外原因。
- 收藏与最近访问入口遵从当前会话的页面权限与组织范围；授权收窄后隐藏失效入口，保留个人偏好记录以供恢复授权后使用。任务中心的模型调用记录入口同时要求 `tasks:read` 与全组织授权。
- 使用独立用户身份和角色授权，组织树不是数据授权。应用使用 HttpOnly Cookie 会话及 CSRF/Origin 校验，不保留继承的令牌登录旁路或可绕过的新旧双入口。
- 未登录返回 401；已登录但无操作权限返回 403。对象不可见时按接口一致返回 404 或受控拒绝，不在列表、引用、错误或日志查询中泄露其存在。
- service 接受经服务端构建的用户/角色/组织上下文；工具、任务、下载、报表和搜索使用同一范围校验。
- 用户停用或授权变化后，持久任务执行前重新授权；不能用队列中的旧范围继续读取受限数据。
- 初始化首个管理员采用明确操作，不附带默认固定密码或隐式登录后门。密码/模型凭据不写入审计正文或 API 回显。

## 业务错误与写入一致性

HTTP 状态是传输表达，业务码才是稳定契约。参数格式错误、上下文冲突、权限不足、重复请求、锁期/版本冲突、任务容量超限和外部能力不可用必须可区分。

导入预览绑定文件指纹、操作者、目标范围与相关版本；确认时重验并复用幂等控制。批次、事实和成功状态原子提交，失败完整回滚并记录明确失败。模型请求、长解析不在写事务里。

具体表、索引、字段默认值和迁移回退不得仅从以上概念表自动推导；它们是领域实施前的交付物，见 T-1 和 T-2。
