# 需求与范围

状态：项目方向已确定，功能条目是待实现的需求基线。验收结果见[验收规范](acceptance.md)。

## 产品目标

服务单人维护、单机部署的水利财务分析业务；在 newbd 已有组织、科目、预算版本、实际快照、分析和助手上扩展业务。newfc 的代码基础是 newbd；lishui 用于业务需求、规则和样本参考。

## 范围边界

- 保留费用报销审核、合同、投资、项目/经营预算、计划、财报、管理会计、风险与报告等业务。
- 通过 EAS 导出 Excel/CSV 和业务台账取得数据；不建设总账记账、支付、真实 EAS 直连或写回。
- 不复制 Dify/DB-GPT 平台入口、供应商权限码、旧 Compose 或全部历史文档。
- 沿用 newbd 的交互和模块基础，覆盖确认的业务结果，不要求旧 lishui URL、API 和表结构原样兼容。
- 不为当前单套部署引入多租户、微服务或常驻中间件平台。
- 功能以业务流程和结果验收，不能只按页面数量或同名菜单认定覆盖。

## 用户操作与职责

| 职责 | 典型操作 | 必须具备的边界 |
|---|---|---|
| 数据维护 | 上传、预览、确认导入、主数据映射 | 组织范围、幂等、原件和批次证据 |
| 财务分析 | 预实对比、财报、指标、投资分析 | 同期间/组织/版本事实，金额口径可追溯 |
| 业务复核 | 费用/合同复核、报告审批、更正审核 | 真实用户身份、状态检查、明确权限与审计 |
| 系统管理 | 用户/角色、配置、任务与恢复 | 授权管理与业务审批分别控制 |

这些是能力划分，不预设必须有四个固定角色或不同人员。审批的具体自审限制与原业务规则核对后在对应领域设计中固定；单人使用不意味着取消权限验证。

## 事实边界

经营预算与实际快照复用 newbd 的事实源；项目、合同、报销和投资建立各自领域事实并通过明确关系关联。预算实际数不代替 EAS 原始凭证，预算版本定稿不代替财务期间锁定。

API 操作清单在领域设计时登记“继承、扩展、新建或明确退出原因”。26 个入口不代表已穷尽模块内部流程，管理会计八个子功能、费用人工复核、报告发布和投资模型需继续拆到可验证场景。
