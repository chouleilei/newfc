## T-3：财务数据与分析

涉及功能：eas_workspace（AC-F05）、data_governance（AC-F06）、financial_statements（AC-F10）、management_accounting（AC-F14）、standard_reports（AC-F19），并扩展 dashboard、xiaoli_assistant、audit_log；跨域 AC-X03～X06。参考 lishui 的 eas_workspace、governance、financial_statement、management_accounting、finance_report_service 及测试（只读），不照搬表结构和 URL。

### 公共基础

- **文件对象**（`modules/files`）：原件按内容寻址、不可变，存放于 `<数据目录>/objects/sha256/<前 2 位>/<sha256>`。先写临时文件、fsync 后原子改名，再在短事务里登记 `file_object`（sha256 唯一、大小、类型、首次名称、创建人）。相同内容复用同一对象，业务表只引用 `file_object_id` 并保存自己的文件名。没有按 ID 直接下载的接口，下载只能经业务对象的 service，先按业务对象鉴权。登记失败时磁盘上可能留下无引用文件，由 `sweepOrphanObjects` 回收“库中无记录且超过 24 小时”的文件。备份和恢复时的对象一致性在阶段 6（AC-X07）验收。
- **契约**：新接口的请求体用 zod 校验，schema 放在 `backend/src/contracts/<domain>.ts`，只依赖 zod。前端通过 `@contracts/*` 别名用 `import type` 取 `z.infer` 类型，构建产物不引入 zod。这就是 architecture.md 要求在首个契约闭环选定的共享契约方案。
- **金额**：原始凭证、余额和报表数值按“元，最多两位小数”解析为整数分：`parseDecimalToCents` 拒绝百分号、科学计数和超过两位的小数，千分位逗号、括号负数和“-”空值由领域解析器显式处理。接口以十进制字符串返回金额。报表中不可解析的文本单元格保留原文并给出提示，不当作 0。比率用 `ratioString`（6 位小数），分母为 0 时返回 null。
- **期间**：`YYYY-MM`。利润表和现金流量表取“本年累计”，资产负债表取“期末余额”，字段名写明口径（`*_ytd` / `*_period_end`）。
- **错误码**：均为 409 冲突，除非另注。
  - 通用：`VERSION_CONFLICT`。
  - EAS：`EAS_PERIOD_LOCKED`、`EAS_IDEMPOTENCY_CONFLICT`、`EAS_RECON_NOT_PASSED`、`EAS_CURRENT_SET_CHANGED`、`EAS_CORRECTION_PENDING`、`EAS_CORRECTION_STATE`、`SELF_REVIEW_FORBIDDEN`（403）。
  - 数据治理：`GOVERNANCE_FACT_MUTATED`。
  - 财务报表：`STATEMENT_INVALID`（422）、`CURRENT_BATCH_CHANGED`。
  - 管理会计：`CALCULATOR_UNAVAILABLE`、`ALLOCATION_STATE`。
  - 标准报表：`REPORT_ALREADY_REVIEWED`。
- **权限**：沿用 T-1 目录。新增两个权限码：`statements:import` 负责财务报表导入与激活；`mgmt:review` 负责分摊调整和绩效复核。预算调整生效需要 `budget:finalize`。标准报表：`report:read` 查看，`report:write` 生成，`report:approve` 复核。凡是“提交人 ≠ 复核人”的规则，只有管理员可以同人复核，且必须填写例外原因并写入审计。

### EAS 原始事实与期间控制（AC-F05）

| 实体 | 要点 |
|---|---|
| eas_batch | data_type（voucher/balance/auxiliary）、org_id、period、file_object_id、文件名、行数、status（candidate/active/superseded）、is_current、correction_id、created_by、幂等键 UNIQUE(org, period, type, sha256) |
| eas_voucher_line / eas_balance_line / eas_aux_line | 源行号、原文字段、金额分；由触发器拒绝 UPDATE/DELETE，批次状态变化不改事实行 |
| eas_recon_set / eas_recon_set_batch / eas_recon_result | 一次预检对应一个集合。规则结果为 passed、warning、incomplete 或 failed，附差异金额（分）和前 100 条明细；集合带 version |
| eas_aux_requirement | 按组织配置需要核对的科目 × 辅助类型 |
| eas_period_lock / eas_period_lock_event | 锁定绑定当前集合，事件记录锁定、解锁和更正切换 |
| eas_correction / eas_correction_review | 锁后更正流程：提交 → 候选导入 → 预检 → 复核 → 原子切换 |

规则：
- 解析支持 CSV（UTF-8/BOM）与 xlsx，按表头别名定位列。先全量校验：
  - 必填列；
  - 公司通过 `resolveEntity(org, sourceSystem='eas')` 唯一解析；
  - 单一公司、单一期间；
  - 凭证日期与期间一致；
  - 凭证只能单边记账，同一凭证借贷平衡；
  - 余额满足“期初 + 本期 = 期末”，辅助核算满足“期初 + 借 − 贷 = 期末”；
  - 金额格式合法；
  - 业务键在文件内唯一。

  全部通过后，才在一个短事务里写入批次和全部行，中途失败不留下批次。同一幂等键再次提交时返回原批次（replay）；已有批次的“组织 + 期间 + 类型”换了新内容，则作为新候选批次，不覆盖旧批次。
- 已锁期间直接导入返回 `EAS_PERIOD_LOCKED`。只能在本人提交、仍处于待导入状态的更正申请下导入候选批次。
- 预检检查以下各项，容差 0.01 元：
  - 三类文件是否齐全，缺失为 incomplete；
  - 凭证按科目的借贷发生额 = 余额表本期借贷；
  - 上期当前集合的期末 = 本期期初。没有上期集合时给 warning，并说明以本期为基线；
  - 已配置的辅助核算要求与余额一致。未配置时给 warning，不阻断。
- 激活要求：集合 passed、version 匹配、期间未锁、不是更正候选。在一个事务里切换当前集合，旧集合的批次变为 superseded。
- 锁定只允许锁“已通过且当前”的集合。解锁需要 `eas:period_lock` 且必须是管理员，填写原因，并且没有待处理的更正。
- 更正：提交时绑定 `expected_current_set_id`；预检通过后进入待复核。批准时重验“当前集合仍是申请时的集合、锁基线未变”，并在同一事务里激活候选集合、把锁基线切到新集合、写入 correction_switch 事件。退回则结束本次申请。
- 与预算实际数的关系：EAS 原始事实不直接写入预算实际数（requirements「事实边界」）；实际快照仍由继承的财务转换（finance-import）生成。

### 数据治理（AC-F06）

- 质量问题 `gov_issue`：
  - 字段：issue_key（来源 + 对象 + 问题类型的哈希，去重）、source_type（eas_recon / eas_master / statement）、source_ref、org_id、period、source_hash（来源事实快照哈希）、status、version。
  - 来源：EAS 预检失败的规则、EAS 凭证中无法解析的项目/供应商编码、财报校验警告。由“扫描”动作生成或刷新。同一问题重复扫描不会产生新问题；原本已解决但再次出现时重新打开。
- 处置 `gov_disposition`：
  - 映射覆盖：写 `md_code_mapping`，退役旧行后新增一行。
  - 误报。
  - 重新导入：关联一个新的、已激活的 EAS 集合。
- 复核 `gov_review`：提交人 ≠ 复核人，同一处置只能复核一次。
- 生效证明 `gov_effect_proof`：记录复核前后的来源哈希。
- 治理从不改写原始事实。重验或生成证明时，如果来源哈希已变化，返回 `GOVERNANCE_FACT_MUTATED`。
- 问题按 org_id 做组织范围裁剪。

### 财务报表（AC-F10）

- 四表模板（资产负债、利润、现金流量、所有者权益变动）解析为表项和事实，每个事实记录来源单元格、公式文本和文本值。公式缺缓存值时给 warning（FORMULA_CACHE_MISSING），不当作 0。
- 勾稽校验：
  - 资产总计 = 负债和所有者权益总计；
  - 负债合计 + 权益合计 = 总计；
  - 期初现金 + 净增加额 = 期末现金；
  - 以上容差 1 元，不平衡为 error；合计行缺失时给 warning。
- 流程为预览 → 导入 → 激活：
  - 预览只解析，不写库；
  - 导入时有 error 则拒绝（STATEMENT_INVALID）。按“组织 + 期间 + 口径 + sha256”幂等：同一文件再次导入返回原批次；
  - 激活需带 expected_current_batch_id，与实际当前批次不一致返回 CURRENT_BATCH_CHANGED；
  - 作废需填写原因。
- 总览只读当前批次，给出语义指标：总资产、总负债、所有者权益、营业总收入（本年累计）、净利润（本年累计）、经营现金流，以及资产负债率等比率。
- 组织范围按报表单位 org_id 裁剪。

### 管理会计（AC-F14，八个子功能）

| 子功能 | 设计 |
|---|---|
| 维度 | `ma_dimension` + `ma_dimension_member`。成员引用主数据（组织、项目、科目）或自定义编码；映射先预览再确认，引用对象必须存在且在范围内 |
| 指标 | `ma_metric` 包括代码、名称、单位（money/ratio）、计算器、参数和阈值。计算器：budget_amount（当前采用预算，按科目汇总）、actual_amount（年度最新实际快照）、execution_rate、eas_balance（当前 EAS 集合的期末余额）、statement_item（当前财报语义指标）、allocated_cost（已确认分摊）。计算结果写入 `ma_calc_run` + `ma_metric_snapshot`，保存数值、证据引用和来源批次。缺少来源时返回 CALCULATOR_UNAVAILABLE 并列出原因，不返回 0。合同、风险、投资、计划的计算器在对应阶段接入 |
| 分摊 | 成本池（归属组织、期间、总额）+ 规则（目标组织 × 权重）。流程为预览 → 确认 → 作废：用 `allocateCents` 分摊，最后一项吸收尾差，保证合计守恒；确认时写入 allocated_cost 快照，作废时快照随之作废 |
| 分摊调整与血缘 | 调整 = 同一运行内两个结果之间转移金额（保持守恒）。提交后复核（提交人 ≠ 复核人）；批准后生效并重写对应快照。血缘链：成本池 → 规则/权重 → 运行 → 结果 → 调整 → 快照 |
| 预算调整 | 针对当前采用的已锁经营预算的一个单元格，流程为提交 → 复核 → 生效。生效时在一个事务里复制出新版本、写入调整后的金额、锁定，并设为当前版本（期望当前版本仍是源版本）。原版本不变 |
| 预警 | 阈值包括上下限（warning/critical），以及“实际相对预算”的偏差比例。扫描指定的计算运行生成预警；同一指标 + 组织 + 期间 + 类型的未关闭预警在重复扫描时只更新，不重复创建。预警流程为确认（原因分类 + 说明）→ 关闭 |
| 责任中心 | 按授权范围内的组织汇总：最新指标快照、未关闭预警、分摊成本、待办（待确认预警、待复核调整） |
| 多维分析 | 在快照上查询：指标 × 期间 × 组织/维度成员分组，返回数值和来源运行 |
| 绩效 | 方案包括指标、权重、目标和方向。评分基于指定的计算运行，保存评分明细；复核可调整分数，但必须保留原分和原因，提交人 ≠ 复核人 |

### 标准报表（AC-F19）

- 生成时冻结 summary、rows 和来源引用（批次、集合、版本、快照 ID），此后页面和导出只读冻结内容。复核后状态变为 reviewed，不能再次复核，并写入审计。Excel 导出与页面内容逐行一致。
- 本阶段的报表类型：
  - 经营预算执行表：复用 report/completion；
  - 财务报表摘要：当前财报批次；
  - EAS 对账结果表：当前集合的规则结果。

  合同付款台账和风险整改台账在阶段 4/5 加入。
- 受限用户只能生成和查看自己授权组织范围内的报表；全组织口径的报表需要全组织权限。

### 页面与助手

- 导航新增“财务数据”分组：EAS 工作区、数据治理、财务报表。另有“管理会计”（八个子功能分页签）和“标准报表”。沿用现有布局、表格和确认对话框；入口按权限显示，受限用户只看到授权组织。
- 工作台在有 statements:read 权限且存在当前财报批次时，显示财报摘要（总资产、资产负债率、净利润本年累计）。
- 助手新增只读工具：`eas_period_status`（org_scope）、`statement_overview`（org_scope）、`mgmt_metric_snapshots`（org_scope）、`mgmt_alerts`（org_scope）。工具调用与页面相同的 service，写操作不暴露给助手。

### 样本与完成条件

- EAS：lishui v600 样本三件套（凭证 6 行、余额 4 行、辅助 4 行）。
  - 逐行金额：`记-0001/1` 借 2,100,000.00，`记-0003/2` 贷 900,000.00，缺失的项目编码保持为空。
  - 预检：三件套齐全，发生额一致，首期连续性为 warning（无上期）；配置 220201 × 项目的辅助核算要求后通过，辅助期末余额按带符号的 −900,000.00 比较。
  - 事务与幂等：同一请求重复提交只有一个批次；文件校验失败时不留批次，也不留事实行。
  - 期间控制：锁期后直接导入返回 409；更正申请由同一人复核被拒绝；两个集合并发激活时出现版本冲突。
- 财报：总资产 1,000,000.00、负债 420,000.00、权益 580,000.00、营业总收入（本年累计）300,000.00、净利润 60,000.00、资产负债率 0.420000；不平衡模板返回 BALANCE_NOT_EQUAL，导入被拒绝。
- 分摊：1,000.00 按 3:1 分摊为 750.00/250.00；100.00 按 1:1:1 分摊为 33.33/33.33/33.34；作废后快照不再有效。
- 越权：受限用户读写范围外组织的批次、集合、锁、更正、问题、财报批次、成本池和报表，均返回 404 或 SCOPE_RESTRICTED；助手的同名工具同样被拒绝。

## 后续领域细设计格式

领域开始实施时，在本文件增加对应小节；只有内容足够独立时再拆单独领域 spec。至少定义：

1. **事实与数据**：实体、来源主键、外键、唯一约束、原始事实与派生结果、当前版本选择规则；组织/项目编码与 newbd ID 的映射。
2. **金额契约**：字段单位、存储精度、可接受范围、舍入时机、金额字符串协议；比率与百分比、零与缺失的区别。继承的 number 金额与新增 BigInt/十进制边界必须显式转换并验证。
3. **状态与事务**：允许的操作、期望版本/幂等条件、锁期约束、失败回滚、审批与冻结规则。必要约束优先复用，避免为所有表统一增加一套机制。
4. **接口与权限**：请求/响应与错误码、分页、文件访问、用户/角色/组织范围；后台任务和 AI 工具使用相同授权上下文，不信任客户端声明的权限。
5. **页面与助手**：沿用 newbd 导航和交互，定义该域入口、表格/详情/编辑、空态/错误和定位；列明可用工具及不支持的问题，避免新建重复页面。
6. **样本与完成条件**：至少包含正常、边界、无数据、错误与越权场景；指定正确金额/状态/证据和对应 Vitest/集成/必要浏览器验收。

首个预算闭环优先完成以上六项，后续领域按依赖推进，无需在初始化仓库前写完所有模块的详细表结构。
