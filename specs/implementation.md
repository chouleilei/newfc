## T-3：财务数据与分析

涉及功能：eas_workspace（AC-F05）、data_governance（AC-F06）、financial_statements（AC-F10）、management_accounting（AC-F14）、standard_reports（AC-F19），并扩展 dashboard、xiaoli_assistant、audit_log；跨域 AC-X03～X06。参考 lishui 的 eas_workspace、governance、financial_statement、management_accounting、finance_report_service 及测试（只读），不照搬表结构和 URL。

### 公共基础

- **文件对象**（`modules/files`）：原件按内容寻址、不可变，存放于 `<数据目录>/objects/sha256/<前 2 位>/<sha256>`。先写临时文件、fsync 后原子改名，再在短事务里登记 `file_object`（sha256 唯一、大小、类型、首次名称、创建人）。相同内容复用同一对象，业务表只引用 `file_object_id` 并保存自己的文件名。没有按 ID 直接下载的接口，下载只能经业务对象的 service，先按业务对象鉴权。登记失败时磁盘上可能留下无引用文件，由 `sweepOrphanObjects` 回收“库中无记录且超过 24 小时”的文件。备份和恢复时的对象一致性在阶段 6（AC-X07）验收。
- **契约**：新接口的请求体用 zod 校验，schema 放在 `backend/src/contracts/<domain>.ts`，只依赖 zod。前端通过 `@contracts/*` 别名用 `import type` 取 `z.infer` 类型，构建产物不引入 zod。这就是 architecture.md 要求在首个契约闭环选定的共享契约方案。
- **金额**：原始凭证、余额和报表数值按“元，最多两位小数”解析为整数分：`parseDecimalToCents` 拒绝百分号、科学计数和超过两位的小数，千分位逗号、括号负数和“-”空值由领域解析器显式处理。接口以十进制字符串返回金额。报表中不可解析的文本单元格保留原文并给出提示，不当作 0。比率用 `ratioString`（6 位小数），分母为 0 时返回 null。
- **期间**：`YYYY-MM`。利润表和现金流量表取“本年累计”，资产负债表取“期末余额”，字段名写明口径（`*_ytd` / `*_period_end`）。
- **错误码**：均为 409 冲突，除非另注。
  - 通用：`VERSION_CONFLICT`。
  - EAS：`EAS_PERIOD_LOCKED`、`EAS_IDEMPOTENCY_CONFLICT`、`EAS_RECON_NOT_PASSED`、`EAS_CURRENT_SET_CHANGED`、`EAS_CORRECTION_PENDING`、`EAS_CORRECTION_STATE`、`SELF_REVIEW_FORBIDDEN`（403）。
  - 数据治理：`GOVERNANCE_FACT_MUTATED`。
  - 财务报表：`STATEMENT_INVALID`（422）、`CURRENT_BATCH_CHANGED`。
  - 管理会计：`CALCULATOR_UNAVAILABLE`、`ALLOCATION_STATE`。
  - 标准报表：`REPORT_ALREADY_REVIEWED`。
- **权限**：沿用 T-1 目录。新增两个权限码：`statements:import` 负责财务报表导入与激活；`mgmt:review` 负责分摊调整和绩效复核。预算调整生效需要 `budget:finalize`。标准报表：`report:read` 查看，`report:write` 生成，`report:approve` 复核。凡是“提交人 ≠ 复核人”的规则，只有管理员可以同人复核，且必须填写例外原因并写入审计。

### EAS 原始事实与期间控制（AC-F05）

| 实体 | 要点 |
|---|---|
| eas_batch | data_type（voucher/balance/auxiliary）、org_id、period、file_object_id、文件名、行数、status（candidate/active/superseded）、is_current、correction_id、created_by、幂等键 UNIQUE(org, period, type, sha256) |
| eas_voucher_line / eas_balance_line / eas_aux_line | 源行号、原文字段、金额分；由触发器拒绝 UPDATE/DELETE，批次状态变化不改事实行 |
| eas_recon_set / eas_recon_set_batch / eas_recon_result | 一次预检对应一个集合。规则结果为 passed、warning、incomplete 或 failed，附差异金额（分）和前 100 条明细；集合带 version |
| eas_aux_requirement | 按组织配置需要核对的科目 × 辅助类型 |
| eas_period_lock / eas_period_lock_event | 锁定绑定当前集合，事件记录锁定、解锁和更正切换 |
| eas_correction / eas_correction_review | 锁后更正流程：提交 → 候选导入 → 预检 → 复核 → 原子切换 |

规则：
- 解析支持 CSV（UTF-8/BOM）与 xlsx，按表头别名定位列。先全量校验：
  - 必填列；
  - 公司通过 `resolveEntity(org, sourceSystem='eas')` 唯一解析；
  - 单一公司、单一期间；
  - 凭证日期与期间一致；
  - 凭证只能单边记账，同一凭证借贷平衡；
  - 余额满足“期初 + 本期 = 期末”，辅助核算满足“期初 + 借 − 贷 = 期末”；
  - 金额格式合法；
  - 业务键在文件内唯一。

  全部通过后，才在一个短事务里写入批次和全部行，中途失败不留下批次。同一幂等键再次提交时返回原批次（replay）；已有批次的“组织 + 期间 + 类型”换了新内容，则作为新候选批次，不覆盖旧批次。
- 已锁期间直接导入返回 `EAS_PERIOD_LOCKED`。只能在本人提交、仍处于待导入状态的更正申请下导入候选批次。
- 预检检查以下各项，容差 0.01 元：
  - 三类文件是否齐全，缺失为 incomplete；
  - 凭证按科目的借贷发生额 = 余额表本期借贷；
  - 上期当前集合的期末 = 本期期初。没有上期集合时给 warning，并说明以本期为基线；
  - 已配置的辅助核算要求与余额一致。未配置时给 warning，不阻断。
- 激活要求：集合 passed、version 匹配、期间未锁、不是更正候选。在一个事务里切换当前集合，旧集合的批次变为 superseded。
- 锁定只允许锁“已通过且当前”的集合。解锁需要 `eas:period_lock` 且必须是管理员，填写原因，并且没有待处理的更正。
- 更正：提交时绑定 `expected_current_set_id`；预检通过后进入待复核。批准时重验“当前集合仍是申请时的集合、锁基线未变”，并在同一事务里激活候选集合、把锁基线切到新集合、写入 correction_switch 事件。退回则结束本次申请。
- 与预算实际数的关系：EAS 原始事实不直接写入预算实际数（requirements「事实边界」）；实际快照仍由继承的财务转换（finance-import）生成。

### 数据治理（AC-F06）

- 质量问题 `gov_issue`：
  - 字段：issue_key（来源 + 对象 + 问题类型的哈希，去重）、source_type（eas_recon / eas_master / statement）、source_ref、org_id、period、source_hash（来源事实快照哈希）、status、version。
  - 来源：EAS 预检失败的规则、EAS 凭证中无法解析的项目/供应商编码、财报校验警告。由“扫描”动作生成或刷新。同一问题重复扫描不会产生新问题；原本已解决但再次出现时重新打开。
- 处置 `gov_disposition`：
  - 映射覆盖：写 `md_code_mapping`，退役旧行后新增一行。
  - 误报。
  - 重新导入：关联一个新的、已激活的 EAS 集合。
- 复核 `gov_review`：提交人 ≠ 复核人，同一处置只能复核一次。
- 生效证明 `gov_effect_proof`：记录复核前后的来源哈希。
- 治理从不改写原始事实。重验或生成证明时，如果来源哈希已变化，返回 `GOVERNANCE_FACT_MUTATED`。
- 问题按 org_id 做组织范围裁剪。

### 财务报表（AC-F10）

- 四表模板（资产负债、利润、现金流量、所有者权益变动）解析为表项和事实，每个事实记录来源单元格、公式文本和文本值。公式缺缓存值时给 warning（FORMULA_CACHE_MISSING），不当作 0。
- 勾稽校验：
  - 资产总计 = 负债和所有者权益总计；
  - 负债合计 + 权益合计 = 总计；
  - 期初现金 + 净增加额 = 期末现金；
  - 以上容差 1 元，不平衡为 error；合计行缺失时给 warning。
- 流程为预览 → 导入 → 激活：
  - 预览只解析，不写库；
  - 导入时有 error 则拒绝（STATEMENT_INVALID）。按“组织 + 期间 + 口径 + sha256”幂等：同一文件再次导入返回原批次；
  - 激活需带 expected_current_batch_id，与实际当前批次不一致返回 CURRENT_BATCH_CHANGED；
  - 作废需填写原因。
- 总览只读当前批次，给出语义指标：总资产、总负债、所有者权益、营业总收入（本年累计）、净利润（本年累计）、经营现金流，以及资产负债率等比率。
- 组织范围按报表单位 org_id 裁剪。

### 管理会计（AC-F14，八个子功能）

| 子功能 | 设计 |
|---|---|
| 维度 | `ma_dimension` + `ma_dimension_member`。成员引用主数据（组织、项目、科目）或自定义编码；映射先预览再确认，引用对象必须存在且在范围内 |
| 指标 | `ma_metric` 包括代码、名称、单位（money/ratio）、计算器、参数和阈值。计算器：budget_amount（当前采用预算，按科目汇总）、actual_amount（年度最新实际快照）、execution_rate、eas_balance（当前 EAS 集合的期末余额）、statement_item（当前财报语义指标）、allocated_cost（已确认分摊）。计算结果写入 `ma_calc_run` + `ma_metric_snapshot`，保存数值、证据引用和来源批次。缺少来源时返回 CALCULATOR_UNAVAILABLE 并列出原因，不返回 0。合同、风险、投资、计划的计算器在对应阶段接入 |
| 分摊 | 成本池（归属组织、期间、总额）+ 规则（目标组织 × 权重）。流程为预览 → 确认 → 作废：用 `allocateCents` 分摊，最后一项吸收尾差，保证合计守恒；确认时写入 allocated_cost 快照，作废时快照随之作废 |
| 分摊调整与血缘 | 调整 = 同一运行内两个结果之间转移金额（保持守恒）。提交后复核（提交人 ≠ 复核人）；批准后生效并重写对应快照。血缘链：成本池 → 规则/权重 → 运行 → 结果 → 调整 → 快照 |
| 预算调整 | 针对当前采用的已锁经营预算的一个单元格，流程为提交 → 复核 → 生效。生效时在一个事务里复制出新版本、写入调整后的金额、锁定，并设为当前版本（期望当前版本仍是源版本）。原版本不变 |
| 预警 | 阈值包括上下限（warning/critical），以及“实际相对预算”的偏差比例。扫描指定的计算运行生成预警；同一指标 + 组织 + 期间 + 类型的未关闭预警在重复扫描时只更新，不重复创建。预警流程为确认（原因分类 + 说明）→ 关闭 |
| 责任中心 | 按授权范围内的组织汇总：最新指标快照、未关闭预警、分摊成本、待办（待确认预警、待复核调整） |
| 多维分析 | 在快照上查询：指标 × 期间 × 组织/维度成员分组，返回数值和来源运行 |
| 绩效 | 方案包括指标、权重、目标和方向。评分基于指定的计算运行，保存评分明细；复核可调整分数，但必须保留原分和原因，提交人 ≠ 复核人 |

### 标准报表（AC-F19）

- 生成时冻结 summary、rows 和来源引用（批次、集合、版本、快照 ID），此后页面和导出只读冻结内容。复核后状态变为 reviewed，不能再次复核，并写入审计。Excel 导出与页面内容逐行一致。
- 本阶段的报表类型：
  - 经营预算执行表：复用 report/completion；
  - 财务报表摘要：当前财报批次；
  - EAS 对账结果表：当前集合的规则结果。

  合同付款台账和风险整改台账在阶段 4/5 加入。
- 受限用户只能生成和查看自己授权组织范围内的报表；全组织口径的报表需要全组织权限。

## T-4：项目、合同与费用

涉及功能：project_budget（AC-F09）、plan_execution（AC-F15）、project_contract（AC-F16）、contract_import（AC-F04）、expense_audit（AC-F22）。同时扩展 management_accounting 计算器、standard_reports（合同付款台账）、dashboard、xiaoli_assistant、audit_log；跨域 AC-X03～X06。参考 lishui 的 project_budget、plan_execution、contract_lifecycle、import_service、expense_audit 及测试（只读），不照搬表结构和 URL，也不照搬以下已知问题：
- 计划执行把“开工累计已完成投资”当作“年度实际”兜底，混淆当期与累计；
- 形象进度缺失时用投资完成比例冒充；

### 公共约定

- **迁移**：V49 项目预算、V50 计划执行、V51 合同、V52 费用审核，追加在 `migrations-newfc.ts`。
- **原件**：复用 T-3 文件对象层。业务表只引用 `file_object_id`，下载经业务 service 鉴权。
- **导入**：复用 `io/table-reader`，流程为预览 → 导入 → 激活/确认，全量校验通过后才在短事务里写入。
- **组织归属**：以主数据为准。
  - 项目行取 `md_project.org_id`；文件里填写的组织与之不符时报错。
  - 无项目编码的行按“承办单位”经 `resolveEntity(org, sourceSystem)` 唯一解析。解析不到或有歧义时报错并给出候选，可在主数据映射里补 `plan`/`contract` 来源映射。
- **金额与数值**：
  - 金额按整数分存储，接口返回十进制字符串。
  - 万元模板按 ×10000 精确换算，超过 6 位小数（折合超过分）时报错，不静默舍入。
  - 比率用 6 位小数定点字符串；形象进度接受“45%”或 0～1 的小数，大于 1 且没有 % 时报错。
  - 数量用 4 位小数定点字符串，不参与金额汇总。
- **组织范围**：一个批次可能跨多个组织。
  - 受限用户只看到范围内的行，也只能看到含有范围内行的批次。
  - 导入、激活、作废要求批次涉及的全部组织都在范围内，否则 `SCOPE_RESTRICTED`（403）。
  - 对象不在范围内时返回 404。
- **复核分离**：提交人 ≠ 复核人。管理员同人复核必须填写例外原因（`security/review.ts`）。
- **错误码**：均为 409，除非另注。
  - 通用：`VERSION_CONFLICT`、`CURRENT_BATCH_CHANGED`、`SCOPE_RESTRICTED`（403）。
  - 导入：`IMPORT_INVALID`（422，附逐行错误）、`PREVIEW_STALE`。
  - 合同：`CONTRACT_STAGE_BLOCKED`（附 blockers）、`CONTRACT_STATE`、`CONTRACT_PAYMENT_EXCEEDS`、`CONTRACT_AMOUNT_BELOW_PAID`、`EVIDENCE_REQUIRED`。
  - 费用：`EXPENSE_STATE`、`EXPENSE_REVIEW_INCOMPLETE`（422）。

### 项目预算（AC-F09）

- **实体**：
  - `pb_batch`：年度、执行期间 YYYY-MM（须在年度内）、名称、原件、status（imported/voided）、is_current、作废原因、创建/激活/作废人。
  - `pb_entry`：来源行号、project_id、org_id、资金来源、费用类别、年度预算分、已执行分、执行月份。
  - 约束：每批 UNIQUE(project, 资金来源, 组织, 费用类别, 月份)；同一“年度 + 期间”最多一个当前批次，用部分唯一索引保证。
- **解析**：
  - 只接受 xlsx，表头在前 20 行内按别名定位。
  - 必填：项目编码、项目名称、资金来源、年度预算、已执行金额、执行月份。
  - 项目必须存在且启用，名称与编码一致。
  - 金额非负；行期间必须等于本次导入期间。
- **流程**：预览不写库；导入按“年度 + 期间 + sha256”幂等（replay 返回原批次）；激活需带 expectedCurrentBatchId；作废必须填原因。
- **汇总**：按当前批次（或指定批次）计算年度预算合计、已执行合计、剩余、执行率；执行率在预算为 0 时为 null。支持按组织/项目过滤。
- **事实边界**：导入、激活、作废和查询都不读写经营预算与实际快照表，测试核对前后表内容不变。

### 计划执行与形象进度（AC-F15）

- **实体**：
  - `plan_batch`：计划年度、实际期间（YYYY-MM，须在年度内）、原件、status、is_current。
  - `plan_item`：sheet、行、序号、名称、类型（detail/category/subtotal）、层级路径、项目、组织。
  - `plan_fact`：字段键、口径 measure、类型（amount/quantity/ratio/text）、值、来源单元格。
  - 约束：UNIQUE(batch, sheet, row, field)；同一“年度 + 实际期间”最多一个当前批次。
- **模板**：三张表（固定资产投资计划、固定资产购置计划、运行维护费），其余 sheet 忽略并列出。
  - 表头年度与上传年度不一致时报错。
  - 投资明细行缺项目编码报错。
  - 数值不可解析报错；空单元格即缺失，不当 0。
- **口径**：每个字段声明 measure，指标只按口径取数，不互相兜底。
  - `annual_plan`：本年计划。
  - `annual_actual_ytd`：本年截至实际期间的累计实际。
  - `cumulative`：开工累计，如已完成投资、已付款。
  - `total`：总额，如总投资、批复概算、合价。
  - `snapshot`：状态或形象进度。
- **同年取数规则**：概览、项目进度、管理会计计算器、助手工具和报表共用一条规则。
  - 对指定年度，取实际期间 ≤ asOfPeriod（缺省为最新）的最新一个当前批次。
  - 当期发生额 = 本期 annual_actual_ytd − 同年上一实际期间当前批次的 annual_actual_ytd。
  - 没有上期批次时当期为 null，并说明原因“无同年上期批次”；跨年不相减。
- **指标**：
  - 投资：年度执行率 = 年度实际 / 年度计划；累计完成率 = 已完成投资 / 项目总投资。
  - 购置：只有存在实际列时才计算完成率。
  - 运维：年度实际 / 年度计划。
  - 行状态：年度执行率为 null → 不可计算；> 1 → 超计划；< 0.3 → 偏慢；其余正常。
- **项目进度**：投资明细按项目给出批复概算、总投资、已完成（累计）、年度计划与实际、形象进度（仅来自形象进度列）、已付款、状态。

### 合同生命周期（AC-F16）

- **实体**：
  - `ct_contract`：规范化编号唯一、名称、类型、org_id、project_id、supplier_id、原始金额、已批准变更合计、已付合计、阶段、status、签订/生效日期、来源（manual/import）、version。当前金额 = 原始金额 + 已批准变更。
    - status：active、closed、terminated、voided。
    - 阶段：需求立项 → 招采准备 → 合同起草 → 审批签署 → 履约执行 → 变更结算 → 归档关闭。
  - `ct_document`：类型（procurement/contract_text/signed/performance/acceptance/invoice/change/settlement/other）、原件、名称、上传人；不可修改。
  - `ct_review`：审批签署阶段的合同审核，对应一个合同正文文档。
  - `ct_change`：带符号的变更金额、原因、证据文档。
  - `ct_payment`：节点名、申请金额、计划日期、证据文档；支付时登记日期、凭证号、发票文档。
  - `ct_event`：只追加，由触发器禁止改删。
- **阶段推进**：只能前进到下一阶段，推进前服务端重算 blockers，有 blocker 时返回 `CONTRACT_STAGE_BLOCKED`。
  - 需求立项：需要项目、组织、类型。
  - 招采准备：需要 procurement 文档。
  - 合同起草：需要编号、金额 > 0、供应商、contract_text 文档。
  - 审批签署：需要已批准的审核、签订日期、signed 文档。
  - 履约执行：需要 performance 或 acceptance 文档。
  - 变更结算：没有未结变更和未结付款、已付 ≤ 当前金额、有 acceptance 文档，才能进入归档关闭。
- **命令**：
  - 终止（terminate）、作废（void）：必须填原因。
  - 重开（reopen）：需要 contract:review、原因、非归档目标阶段。
  - 已关闭、终止或作废的合同拒绝其余写操作（`CONTRACT_STATE`）。
- **审核**：
  - 在审批签署阶段提交，绑定合同正文文档。
  - 由 contract:review 批准或驳回，同一审核只能处理一次。
  - 审核期间合同正文文档不可再替换，新增正文文档后需重新提交。
- **变更**：
  - 只在履约执行、变更结算阶段提交，必须附证据。
  - 复核批准后在同一事务里累加已批准变更。
  - 若导致当前金额 < 已付，拒绝（`CONTRACT_AMOUNT_BELOW_PAID`）。
- **付款**：
  - 只在履约执行、变更结算阶段申请，状态为 submitted → approved/rejected → paid。
  - 申请和批准时校验“已批准未付 + 已付 + 本次 ≤ 当前金额”，否则 `CONTRACT_PAYMENT_EXCEEDS`。
  - 登记支付必须附 invoice 文档（`EVIDENCE_REQUIRED`），支付后累加已付。
  - 每步写事件并审计。

### 合同导入（AC-F04）

- **文件**：CSV 或 xlsx。表头别名：合同编号、合同名称、项目编码、供应商、合同金额、已付款金额、签订日期、合同类型、责任组织（编码或名称）、付款上限比例。
- **行校验**：
  - 编号在文件内唯一；
  - 金额合法且 > 0，已付 ≤ 金额；
  - 付款上限比例必须带 %（“50”有歧义，拒绝）；
  - 签订日期在 1990-01-01 至今后一年之间；
  - 项目、供应商、组织经主数据唯一解析。
- **预览**：`ct_import` 记录文件 sha256、操作者、逐行计划动作（create/update/unchanged）、逐行错误和计划哈希；不写合同。
  - 已存在的合同按规范化编号匹配。
  - 只更新名称、类型、签订日期、供应商（仅需求立项至合同起草阶段）。
  - 金额不一致记行错误（须走变更流程）。
  - 导入累计已付作为 `import_baseline` 付款，已有正式付款时不能变更。
- **确认**：
  - 只能由预览人对同一文件确认，否则 `PREVIEW_OWNER_MISMATCH`（403）。
  - 确认时重新计算计划，与预览不一致返回 `PREVIEW_STALE`。
  - 有行错误时拒绝。
  - 在一个事务内创建或更新合同并写事件；中途失败全部回滚，预览保持可重试。
  - 重复确认返回原结果（replayed）。

### 费用审核（AC-F22）

- **来源**：newfc 与 EAS 没有网络连接，报销单在本系统原生登记，不接 EAS 推送和回调。
- **实体**：
  - `ex_claim`：单号唯一、org_id、申请人、部门、费用类型、金额、发生日期、说明、status、review_version、提交时的内容哈希。
    - status：draft → submitted → audited → reviewed，另有 supplement（退回补件）。
  - `ex_claim_line`：费用类型、金额、发票号、发票日期。
  - `ex_attachment`：原件、名称、类型提示。
  - 提交后单据内容冻结，只有退回补件后才能追加附件。
- **制度依据**：
  - `ex_policy`：编码、标题、版本、生效起止、来源原件、status。
  - `ex_policy_clause`：条款号、原文、适用费用类型、金额上限（可空）、所需材料关键字。
  - 由 expense:review 维护，变更写审计。
  - 规则按发生日期取当时有效的条款，阈值和材料要求来自条款，不写死。
  - 没有适用条款时给出 `POLICY_BASIS_MISSING`，进入待复核。
- **审核运行**：`ex_audit_run` + `ex_finding` 只追加，由触发器保护。以后台任务执行，不持有写事务。
  1. OCR：仅在配置了 `integration.ocr_*` 时调用，适配契约见运行手册；结果按附件 sha256 缓存。未配置、超时或失败时生成 `OCR_UNAVAILABLE`/`OCR_FAILED` 发现，不当作通过。
  2. 确定性规则：必填、明细合计 = 单据金额、条款金额上限、材料齐套（按条款关键字核对附件名与 OCR 文本）、同单重复发票号或附件、发生日期晚于提交日期、发票日期早于发生月。
  3. 模型语义建议：仅在配置了模型时生成，输出须引用已有证据和条款 ID，校验不通过的丢弃并记录 `MODEL_OUTPUT_INVALID`；未配置时记录 `MODEL_UNAVAILABLE`（info）。
  4. 每条发现带来源（rule/ocr/model）、严重度、证据引用（字段/明细/附件/OCR 页/条款）。运行给出风险等级。任何结果都只是“待复核”，AI 不自动通过。
- **人工复核**：
  - 复核人 ≠ 提交人，须带 expectedReviewVersion。
  - 结论为 pass、reject 或 supplement_required。pass/reject 必须处置全部发现；高风险 pass 必须填例外原因；supplement_required 至少一项标为缺失材料。
  - 复核记录不可改删，结论不可变。pass/reject 为终态；补件后重新提交，生成新的审核运行和新的复核。

### 投资可行性测算（AC-F12）

- **模型**：移植 lishui 的 standard-1.0 计算模型（`docs/investment-feasibility-standard-model.md`、calculator/financing_schedule/sensitivity/risk_rules）。
  - 输入金额单位为万元，最多 6 位小数（折合 1 分，量化后与分精确对应）。
  - 比率为 0～1 的小数，最多 6 位；年份为整数。
  - 每个中间结果按 6 位小数 HALF_UP 量化，口径与 Python Decimal `quantize` 一致。
  - 税费：
    - 含税/不含税拆分；
    - 进项税留抵池滚动；
    - 水资源税 = 发电量 × 税额；水利建设基金 = 不含税收入 × 费率；附加 = 实缴增值税 × 税率。
  - 所得税：项目口径以 EBIT 计税，股权口径以 EBIT − 利息计税，两者分别按年限结转亏损。
  - 融资：
    - 自动计划 = 投资 × 债务比例；
    - 人工计划须覆盖全部建设年，且只覆盖建设年；
    - 资本化利息 = (期初余额 + 当年提款/2) × 利率；
    - 还款方式：等额本金 / 等额本息 / 到期一次。
  - 折旧：直线法；基数 = 投资 + 资本化利息 − 流动资金。
  - 折现：因子为 (1+r)^(年−基准年+1)，首年除以 1.08。
  - IRR：[−0.999, 1] 二分，上界最多加倍 20 次，残差容差 max(1e−6, 1e−7·max|v|)。
    - 状态 success / no_solution / no_convergence，与是否达到基准分开记录；多次变号标记为非常规现金流。
  - 回收期：按累计转正年插值。
  - DSCR：只在运营期还本付息 > 0 时计算。
  - 评分：100 − 30（NPV<0）− 25（IRR 未达基准或无解）− 25（DSCR 不足）− 20（资金缺口）。
  - 模型检查：资金平衡、资本化利息口径、贷款期限拆分、债务期末清零、还本闭合、投资年份、投资为正。有 error 级检查未通过时，仍保存结果并标记 `allChecksPassed=false`，风险扫描会产生对应风险。
- **实体**：
  - `if_project`：编码唯一、名称、`org_id`、可选 `md_project_id`、建设起年、运营起年、测算年限、状态 active/archived。
  - `if_scenario`：项目内编码唯一、名称、`assumptions_json`（规范化十进制字符串）、`assumptions_hash`、来源 `file_object_id`、`version`。
  - `if_run`：方案、类型 base/sensitivity、冻结的输入与 hash、模型版本、状态 succeeded/failed、`result_json`（逐年现金流、指标、检查）、错误、运行人与时间。
    - `if_run` 不可修改、不可删除（触发器保证）。
- **流程**：
  - 方案输入有两种来源：页面编辑（标量参数 + 分年/收入/成本表），或按标准模板 xlsx 导入（预览 → 确认，确认核对 sha256；输入区禁止公式，未知工作表或列报错）。
  - 测算：在事务外计算，再在短事务里写入运行记录。
  - 页面“当前结果”取该方案最新成功运行；运行 hash 与方案当前 hash 不同时，提示“参数已修改，结果需重算”。历史运行只读，可追溯。
  - 敏感性分析：对 7 个标准变量（电价、发电量、运营成本、建设投资、建设延期、贷款利率、期初进项留抵）按设定变动逐项重算。
    - 延期时折现基准锁定在原建设起年；
    - 结果为各指标相对基准的变化，作为 sensitivity 运行冻结保存。
  - 导出：结果 xlsx（摘要、参数、现金流、债务、检查），数值单元格与冻结结果逐项一致。

### 投资控制（四算对比，AC-F13）

- **版本类型**：投资估算 `estimate`、设计概算 `design_estimate`、调整概算 `adjusted_estimate`、施工图预算 `construction_budget`、竣工结算 `settlement`、竣工决算 `final_account`。
- **红线**：优先取已确认的调整概算当前稿，否则取设计概算当前稿；快照记录红线版本 ID。
- **实体**：
  - `ic_project`：`md_project_id` 唯一，组织取主数据；批复概算金额（分）、批复文号、状态。
  - `ic_version`：类型、同类型稿号、名称、状态 draft/confirmed/voided、同类型唯一当前稿（部分唯一索引）、来源文件、批复文号与日期、静态/动态合计（分）、`content_hash`。
  - `ic_item`：
    - 科目编码（`1`、`1.1`、`1.1.1`，层级由编码推导，父编码必须存在）、名称、分类、静态金额（分）、动态金额（分）、来源单元格；
    - `canonical_code` 与映射状态 matched/need_mapping/manual/ignored。
  - `ic_comparison`：冻结快照，不可修改。包括：
    - 基准与目标版本 ID 及其 `content_hash`、红线版本；
    - 阈值副本；
    - 逐科目行、汇总与控制链状态；
    - 运行人与时间。
- **导入**：
  - 模板列为“科目编码、科目名称、分类、静态投资、动态投资”，单位万元（×10000 精确换算，超过分精度报错）。
  - 全量校验：编码格式、编码重复、父级缺失、父级金额 ≠ 子级合计（差额 > 0.01 元为错误）、负数、名称为空。
  - 通过后在短事务里创建草稿版本。
- **映射**：
  - 规范科目树以红线版本为准；尚无红线时，设计概算或估算的科目即规范科目，状态直接 matched。
  - 其他版本先按编码匹配，再按规范化名称匹配；只有唯一名称匹配才建议映射，其余进入 need_mapping。
  - 用户逐项确认或忽略；确认版本时，仍有 need_mapping 且金额 ≠ 0 的行返回 `IC_UNMAPPED_ITEMS`。
- **对比**：选择同项目两个已确认版本。
  - 按规范科目聚合；偏差额 = 目标 − 基准；偏差率 = 偏差额/基准（6 位小数）。
    - 基准为 0 时偏差率为 null，状态 `new_item`；
    - 目标为 0 时为 −1.000000，状态 `removed_or_zero`。
  - 等级按 |偏差率|：≤3% normal，≤8% attention，≤10% warning，>10% exceed。阈值可在请求中覆盖，并写入快照。
  - 控制链（静态金额）：
    - 预算 > 概算 → `budget_over_estimate`；
    - 结算 > 预算 → `settlement_over_budget`（未超红线时不标超概）；
    - 结算或决算 > 红线 → `over_redline`。
  - 版本作废或新导入不改变旧快照；历史对比列表可查看、可导出 xlsx，与快照逐行一致。
- **超限提示**：写在快照汇总中（超限科目数、控制链状态）；需要闭环处理的事项由风险扫描规则生成风险事件。

### 财务预测（AC-F11）

- **定位**：lishui 的预测模型是 Univer 在线工作簿加独立 Node 计算服务。newfc 不引入该服务，改为内置受限公式引擎，工作簿以 JSON 保存。
  - xlsx 导入读取值与公式（exceljs）。
  - 公式覆盖（OPEN-06 的公式部分）：
    - 四则运算、`^`（仅整数指数）、比较、`&`、百分号；
    - 单元格引用、区域引用、跨工作表引用；
    - 函数：SUM、AVERAGE、MIN、MAX、COUNT、ABS、ROUND、ROUNDUP、ROUNDDOWN、IF、IFERROR、AND、OR、NOT、SUMPRODUCT、NPV、IRR、PMT。
  - 不支持的函数、外部引用或 `#REF!` 在导入诊断中列出。
- **实体**：
  - `ff_model`：名称、`org_id`、基准年、预测年数、状态 active/archived、创建人。
  - `ff_version`：
    - 模型内序号、状态 draft/frozen；
    - `workbook_json`：工作表 → 单元格（值或公式），上限 50 个工作表、200,000 个单元格；
    - 参数映射（key、名称、单元格、单位、上下限）、输出映射（key、名称、单元格或一行区域、单位）；
    - 诊断、`content_hash`、来源文件、冻结人与时间。
  - `ff_run`：
    - 版本、类型 baseline/scenario、方案名、参数覆盖（冻结）；
    - 状态 queued/running/succeeded/failed；
    - 输出（6 位小数字符串）、错误码与信息、诊断、`job_id`、耗时、运行人。
- **状态**：
  - 草稿版本可编辑单元格与映射（需期望版本号）。
  - 冻结要求诊断中没有错误。冻结后工作簿、映射与参数不可修改（`FORECAST_VERSION_FROZEN`，触发器兜底）；要修改，只能复制为新草稿。
  - 正式运行只针对冻结版本：
    - 无参数覆盖的运行即基准运行，每个版本最多一个成功的基准运行；
    - 情景运行冻结参数与方案名，结果可与基准逐项对比差异。
- **重算失败**：公式引擎在 Worker 中计算，以下情况运行记为 failed，只保存错误与诊断，不保存部分输出：
  - 循环引用：`FORECAST_CYCLE`；
  - 输出单元格为错误值 `#DIV/0!` `#VALUE!` `#NUM!` `#REF!` `#NAME?`：`FORECAST_FORMULA_ERROR`，附单元格定位；
  - 参数越界：`FORECAST_PARAM_INVALID`；
  - 超时（默认 30 秒）：`FORECAST_TIMEOUT`；
  - 超出内存或计算步数上限：`FORECAST_RESOURCE_LIMIT`。
  - 失败后 Worker 已终止、任务槽已释放，下一次运行可以立即执行。

### 风险闭环（AC-F17）

  | `PLAN_LOW_EXEC` | 计划执行当前批次 | 年度执行率低于阈值 | 0.50 |
  | `CONTRACT_PAY_OVER_CAP` | 进行中合同 | 付款比例超过付款上限比例，且尚未进入结算 | — |
  | `IC_OVER_REDLINE` | 投资控制 | 每个项目最新对比快照中的控制链状态 | — |
  | `IC_CONTROL_BREAK` | 投资控制 | 同上 | — |
  | `IC_DEVIATION_EXCEED` | 投资控制 | 同上 | — |
  | `FEAS_NPV_NEGATIVE` | 可行性测算 | 每个方案最新成功运行的指标与模型检查 | — |
  | `FEAS_IRR_LOW` | 可行性测算 | 同上 | — |
  | `FEAS_DSCR_LOW` | 可行性测算 | 同上 | — |
  | `FEAS_FUNDING_GAP` | 可行性测算 | 同上 | — |
  | `FEAS_MODEL_CHECK` | 可行性测算 | 同上 | — |

- **实体**：
  - `risk_event`：
    - `event_key` 唯一，格式为“规则:对象类型:对象 ID[:子项]”，不含批次，同一对象跨批次不拆成多条；
    - 规则、等级 high/medium/low、`org_id`、可选项目、对象引用、标题、触发说明；
    - 金额（分，可空）、度量值（字符串）、证据 JSON；
    - 状态、命中次数、首次/最近命中、最近扫描是否仍命中；
    - 责任人、整改期限、提交人、`version`。
  - `risk_action`：时间线，只追加（触发器保证），记录类型、前后状态、说明、附件 `file_object_id`、操作人。
  - `risk_scan`：扫描范围、新增/更新/重开/未再命中计数、执行人。
- **状态机**：

  | 当前状态 | 可转到 |
  |---|---|
  | `open`（待确认） | `confirmed`、`false_positive` |
  | `confirmed` | `rectifying`、`false_positive` |
  | `rectifying` | `rectified`（提交复核，必须填写整改说明） |
  | `rectified` | `closed`（复核通过）、`rectifying`（复核退回） |

  - 复核与误报认定需要 `risk:review`，复核人 ≠ 提交整改的人。
  - 其他跳转返回 `RISK_STATE`，closed 与 false_positive 是终态（除重开外）。
  - 每次转换在同一短事务里写时间线与审计。
- **重复触发**：扫描先在事务外计算命中，再在一个短事务里批量写入。
  - 同一 key 未关闭：更新金额与说明，命中次数 +1，记一条 redetect，不重复建单。
  - 已关闭又命中：重开为 open，时间线记 reopen。
  - 误报：只记次数，不重开。
  - 范围内本次未命中的未关闭事件：只标记“最近扫描未命中”，不自动关闭。
  - 受限用户只扫描并写入范围内对象。
- **风险整改台账**（标准报表 `risk_rectification_ledger`）：冻结风险编号、规则、等级、状态、组织、责任人、期限、是否逾期、最近动作与来源事件版本。

### 分析报告（AC-F18）

- **来源**：沿用助手的确定性组稿（`assistant/report-draft.ts`：执行月报、年度复盘、预算讨论材料），新增“风险与投资专题”（风险统计、投资控制超限、可行性指标）。
  - 事实与引用由后端计算；模型只改写叙述，在事务外调用，失败时保留模板叙述并记录模型状态。
- **实体**：
  - `rpt_report`：
    - 系列号、修订号、上一修订 ID、标题、类型、参数、`org_id`；
    - 状态 draft/pending_approval/approved/published/superseded、`version`；
    - 提交、审批、发布的人与时间，例外原因。
  - `rpt_section`：顺序、标题、正文（可编辑）、冻结事实 JSON、引用。
  - `rpt_section_edit`：修改历史，只追加。
  - `rpt_publication`：
    - 发布快照 JSON 与 sha256，以及 DOCX/PDF 两个 `file_object_id`；
    - 快照中手机号与身份证号脱敏；
    - 不可修改（触发器）。
- **状态**：

  | 操作 | 允许的起始状态 | 权限与要求 |
  |---|---|---|
  | 编辑章节 | draft | 需期望版本号 |
  | 提交 | draft | 空章节阻断，返回 `REPORT_INCONSISTENT` |
  | 退回 | pending_approval | 回到 draft，保留意见 |
  | 审批 | pending_approval | `report:approve`，审批人 ≠ 提交人（管理员例外须填原因）；通过后内容冻结 |
  | 发布 | approved | `report:publish` |
  | 修订 | published | 生成新 draft（修订号 +1，复制章节）；新修订发布时旧版本置为 superseded |

  - 发布在任务中渲染，由同一快照渲染 DOCX 与 PDF 并保存为文件对象。
  - 已发布报告不可编辑，只能修订。
- **导出**：
  - 已发布：下载保存的产物，多次下载字节一致。
  - 草稿/审批中：即时渲染，带“草稿”水印。
  - DOCX 与 PDF 的段落文本序列一致（测试分别从 DOCX XML 与 PDF 内容流提取文本并比对）。
  - PDF 使用 Adobe-GB1 预置字体 STSong-Light（UniGB-UCS2-H），不嵌入字体文件，不依赖系统字体。

### 联动、页面与助手

- **管理会计计算器**：
  - `risk_open_amount`：组织内未关闭风险金额；
  - `investment_deviation_rate`：组织内各项目最新对比快照的静态总偏差率（Σ偏差/Σ基准）。
- **工作台待办**：待确认风险、待复核整改、待审批报告、待发布报告。
- **导航**：
  - “投资与预测”：可行性测算、投资控制、财务预测；
  - “风险与报告”：风险台账、分析报告。
- **助手只读工具**：
  - `feasibility_result`、`investment_comparison`、`forecast_runs`、`risk_summary` 为 org_scope；
  - `report_list` 为 org_scope，只返回已发布或本人可见的报告；
  - 写操作（测算、扫描、状态流转、审批发布）不暴露给助手。

### 样本与完成条件

- **可行性**：宜冲桥脱敏样本（lishui fixture）。
  - 2028 年：
    - 含税收入 2100.000000、不含税 1934.862385、销项税 165.137615；
    - 期初留抵 500.000000、实缴 0.000000、期末留抵 352.862385；
    - 水资源税 5.000000、水利建设基金 9.674312。
  - 三种还款方式期末债务均为 0.000000，建设期 DSCR 为空。
  - 首年折现 = 净现金流/1.08 量化。
  - 延期 1～3 年 NPV 下降；基准 IRR 0.99 时计算成功但未达标。
  - 人工融资计划的资本化利息检查通过；无债务与有债务的项目现金流差额恰为所得税差额。
  - 旧 schema 版本被拒。
  - 用独立 Python Decimal 参照实现对全部逐年字段与指标做交叉核对，结果记入验收记录。
- **投资控制**：
  - 基准 100、目标 108 → 偏差 8、偏差率 0.080000、attention；
  - 基准 0 → 偏差率 null、new_item；目标 0 → −1.000000、removed_or_zero；
  - 有调整概算时红线取调整概算；
  - 结算 > 预算但未超红线 → 只有 `settlement_over_budget`；
  - 有未映射金额时确认被拒，映射后通过；
  - 源版本作废后旧快照不变；导出与快照一致。
- **预测**：
  - 样本模型：收入增长、成本、现金流，用 SUM/IF/NPV/IRR/PMT 计算；输出与手算值一致；情景参数改变后差异正确。
  - 失败场景：循环引用、`#DIV/0!` 输出、超时（死循环式大计算）各记为 failed，没有部分输出；随后立即成功运行一次，证明资源已释放。
  - 冻结版本修改被拒。
- **风险**：
  - 扫描产生风险；再扫只更新命中次数；按 确认 → 整改 → 提交 → 他人复核 关闭；再触发时重开；
  - 误报不重开；非法跳转与同人复核被拒；
  - 受限用户扫描与列表只含范围内风险；
  - 整改台账冻结后不随风险变化而变。
- **报告**：
  - 生成 → 编辑 → 提交 → 同人审批被拒（管理员带例外原因可以）→ 审批后编辑被拒 → 发布；
  - DOCX/PDF 文本一致、重复下载字节一致；
  - 修订生成修订号 2 的草稿，原发布版本不变；新修订发布后旧版本为 superseded。
- **越权**：受限用户访问范围外的项目、方案、版本、快照、模型、运行、风险、报告及其下载，返回 404 或 `SCOPE_RESTRICTED`；助手同名工具同样拒绝。

## 后续领域细设计格式

领域开始实施时，在本文件增加对应小节；只有内容足够独立时再拆单独领域 spec。至少定义：

1. **事实与数据**：实体、来源主键、外键、唯一约束、原始事实与派生结果、当前版本选择规则；组织/项目编码与 newbd ID 的映射。
2. **金额契约**：字段单位、存储精度、可接受范围、舍入时机、金额字符串协议；比率与百分比、零与缺失的区别。继承的 number 金额与新增 BigInt/十进制边界必须显式转换并验证。
3. **状态与事务**：允许的操作、期望版本/幂等条件、锁期约束、失败回滚、审批与冻结规则。必要约束优先复用，避免为所有表统一增加一套机制。
4. **接口与权限**：请求/响应与错误码、分页、文件访问、用户/角色/组织范围；后台任务和 AI 工具使用相同授权上下文，不信任客户端声明的权限。
5. **页面与助手**：沿用 newbd 导航和交互，定义该域入口、表格/详情/编辑、空态/错误和定位；列明可用工具及不支持的问题，避免新建重复页面。
6. **样本与完成条件**：至少包含正常、边界、无数据、错误与越权场景；指定正确金额/状态/证据和对应 Vitest/集成/必要浏览器验收。

首个预算闭环优先完成以上六项，后续领域按依赖推进，无需在初始化仓库前写完所有模块的详细表结构。
