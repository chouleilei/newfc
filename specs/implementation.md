# 实施任务与未决事项

状态：规范已整理，所有实现任务未开始。任务完成需要代码与[验收证据](acceptance.md)，不能只勾选本文档。

## 阶段与依赖

| 阶段 | 工作范围 | 完成条件 |
|---|---|---|
| 0. 独立仓库初始化 | 固定源码快照、独立 Git、来源记录、项目标识、配置与数据隔离、systemd 服务模板 | 新目录独立安装/启动，运行不读取原项目配置或数据；继承的核心测试通过，部署路径符合[运行规范](operations.md) |
| 1. 业务基线与关键边界 | 功能覆盖矩阵、样本对照、精度/金额范围、身份与组织上下文、迁移约定 | 财务差异有解释，新增领域调用能执行用户与组织权限；确认必要接口变化 |
| 2. 首个纵向闭环 | 预算导入、汇总页面、带年度/组织上下文的 AI 查询 | 页面与 AI 同源，精度/幂等/失败回滚正确，形成资源测量基线 |
| 3. 财务数据与分析 | EAS 原始事实/治理、期间控制、财报、管理会计 | 批次切换/更正、对账、分摊与快照按样本验收 |
| 4. 项目、合同与费用 | 项目预算、计划、合同生命周期、费用规则/附件/复核 | 事实源明确，权限与状态流转正确，证据可追溯 |
| 5. 投资、预测与报告 | 可行性/投资控制、预测重算、风险闭环、报告审批发布 | 计算结果与确认基准一致，结果冻结、导出及重任务限制有效 |
| 6. 全量覆盖与切换准备 | 跨域工作台/检索、任务/设置、独立数据迁移与备份恢复 | 覆盖矩阵逐项完成或明确验收差异，迁移金额数量可核对，故障恢复与资源验收通过 |

各阶段复用 newbd 现有能力，不重复建设第二套助手、预算或文件底座。权限必须尽早落实，不能在所有领域完成后才补。新项目自身使用功能分支和小步提交，保持唯一正式后端与数据写入路径。
依赖顺序：T-0 → T-1 → T-2；后续领域按各自所需主数据/事实服务开展。阶段 6 的“全量覆盖”必须核对全部 26 项，阶段 2 只代表首个闭环。

### 场景和结果

| 场景 | 前提/操作 | 可判定结果 |
|---|---|---|
| 预算数据闭环 | 固定年度、两家组织、至少收入/成本/费用/数量四类，导入合法模板 | 预览与正式导入一致，事实可定位原件/批次，数量不混入金额 |
| 汇总口径 | 用已确认样本计算组织与集团汇总 | 无重复累计，符号/单位/舍入正确；缺失和零区分 |
| 页面与问答 | 页面选择组织/年度/版本后问执行情况 | 工具读取同源服务，事实与页面一致，答案说明范围并有引用 |

| 模型失败 | 不配置模型/超时/非法参数 | 规则查询可用或明确不支持，不能伪造完成率或“全部正常” |
| 资源 | 重导入同时查询页面和任务进度 | 任务并发有界，达到 OPEN-04 在验收前确定的指标 |

## 后续领域细设计格式

领域开始实施时，在本文件增加对应小节；只有内容足够独立时再拆单独领域 spec。至少定义：

1. **事实与数据**：实体、来源主键、外键、唯一约束、原始事实与派生结果、当前版本选择规则；组织/项目编码与 newbd ID 的映射。
2. **金额契约**：字段单位、存储精度、可接受范围、舍入时机、金额字符串协议；比率与百分比、零与缺失的区别。继承的 number 金额与新增 BigInt/十进制边界必须显式转换并验证。
3. **状态与事务**：允许的操作、期望版本/幂等条件、锁期约束、失败回滚、审批与冻结规则。必要约束优先复用，避免为所有表统一增加一套机制。
4. **接口与权限**：请求/响应与错误码、分页、文件访问、用户/角色/组织范围；后台任务和 AI 工具使用相同授权上下文，不信任客户端声明的权限。
5. **页面与助手**：沿用 newbd 导航和交互，定义该域入口、表格/详情/编辑、空态/错误和定位；列明可用工具及不支持的问题，避免新建重复页面。
6. **样本与完成条件**：至少包含正常、边界、无数据、错误与越权场景；指定正确金额/状态/证据和对应 Vitest/集成/必要浏览器验收。

首个预算闭环优先完成以上六项，后续领域按依赖推进，无需在初始化仓库前写完所有模块的详细表结构。

## 未决事项

| ID | 需要落实的内容 | 解决方式 | 最晚时点/影响 |
|---|---|---|---|
| OPEN-01 | 远程仓库归属、可见性和地址 | 创建远程时确定，不继承原项目 origin | 推送前；不阻塞本地规范和初始化 |
| OPEN-02 | 各域精度、舍入、可支持量程及 BigInt 适配范围 | 核对模型/样本，记录字段契约并测边界 | 对应域表迁移/金额 API 实现前 |
| OPEN-03 | 旧历史、附件、审批/审计/会话的保留范围 | 实际迁入前确认清单与字段映射 | 真实数据迁移前；不阻塞空库开发 |
| OPEN-04 | 文件/行数上限、内存/耗时、缓存/模型并发和恢复窗口 | 固定负载，测试后记录具体目标与结果 | T-2 验收前；恢复指标在业务部署前 |
| OPEN-05 | 模型/OCR 供应商、制度样本、中文召回 | 真实类型样本验证并记录支持/不支持范围 | 费用/知识能力等价验收前 |
| OPEN-06 | 预测公式库覆盖及高精度投资计算 | 核对实际模板与已确认财务样本 | 投资/预测模块实现前 |
| OPEN-07 | Node 精确版本、端口、服务身份及运行路径 | 在新项目检查依赖/ABI/端口，锁定版本配置 | T-0 安装/启动前；不借用原运行依赖 |

未决项只阻塞依赖它的任务。技术细节可在实施中用证据解决，涉及业务含义或历史数据保留的事项需取得明确输入；经过时间或默认值不等于确认。
